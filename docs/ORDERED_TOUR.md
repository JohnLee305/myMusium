# ROUTE-001 · 출입문과 순차 관람 동선

관람객은 첫 방의 입구에서 들어와 지정된 전시품을 순서대로 감상하고, 출구·다음 방 문까지 걸어간다. 연결된 다음 방 입구에서 같은 관람객의 진행을 이어가며 마지막 방의 출구로 퇴장한다. 사용자 카메라의 방 전환으로 관람객을 새로 만들지 않는다.

## 관리 화면

전시실 배치의 **입구·출구와 관람 동선**에서 방을 선택한다.

1. 벽 가장자리의 입구·출구 위치를 선택한다. 위/아래 벽은6곳, 왼쪽/오른쪽 벽은5곳이다. 문은 전시품 칸을 차지하지 않는다.
2. 동선 격자의 빈 칸을 눌러 통행 금지 벽/통로를 바꾼다. 전시품과 벽은 같은 칸에 놓을 수 없다. 가장자리의 벽 칸은 바깥 벽까지 이어진다.
3. 전시품 목록의 위로/아래로 버튼으로 감상 순서를 정한다.
4. 방 목록의 순서를 정한다. 각 방의 출구는 목록의 다음 방 입구와 연결되며 마지막 출구는 박물관 밖이다.
5. **관람 동선 저장**을 누른다. 출구 및 모든 전시품 감상 위치에 도달할 수 있어야 저장된다. 관람 앱을 다시 열어 반영한다.

지금은 방마다 입구1개와 출구1개를 둔 선형 관람 코스다. 여러 갈래 연결문·분기/순환 코스를 편집하는 기능은 포함하지 않는다. 방 내부 통로는 미로 형태로 지정할 수 있다.

## 저장 계약

기존 manifest v1에 선택적인 `roomOrder`와 `rooms[].navigation`을 추가한다. 기존 자료는 수정 없이 방 배열 순서, 전시품의 셀 번호 순서, 아래 벽3번째 입구와 오른쪽 벽1번째 출구로 해석한다.

```json
{
  "roomOrder": ["room-a", "room-b"],
  "navigation": {
    "entrance": {"side": "front", "slot": 2},
    "exit": {"side": "right", "slot": 0},
    "blockedCells": [8, 9],
    "visitOrder": ["artifacts/example/artifact.json"]
  }
}
```

위 예시는 필드 설명용 발췌다. `roomOrder`는 manifest 루트, `navigation`은 해당 방 안에 둔다. 문 slot과 cell은0부터 시작한다. roomOrder는 모든 방을, visitOrder는 해당 방의 모든 전시품을 각각 한 번씩 포함한다.

`POST /api/navigation`은 인증된 JSON 본문(최대256KiB)으로 revision/roomId/navigation/roomOrder를 받는다. 기존 manifest 지문 확인, 연결·멤버십 검사, 백업 후 원자적 저장을 수행한다. 오래된 화면은409로 거절하고 다시 읽는다. 새 전시품은 해당 방 관람 순서 끝에 추가되고 방 이동/휴지통은 순서에서도 항목을 옮기거나 제거한다.

스키마는 기본 구조를 검사한다. 실제 멤버십·문 겹침·통로 연결은 Node/Unity에서 검사한다. `tools/validate-archive.ps1`도 새 동선 자료에 대해 Node 공통 검사를 호출한다(새 동선 검사에는 Node 필요).

## 이동과 방 로딩

관람 목적지의 순서와 거기까지 걸어가는 경로는 별개다. 목적지는 지정한 순서, 바닥 경로는0.4m 간격의 상하좌우 BFS 최단 경로와 장애물 없는 구간 평활화로 계산한다. 기존 탐색기를 확장했으며 A*를 새로 도입하지 않았다. 방 크기16.4×19m, 전시대의 실제 셀 위치·0.8m 앞쪽 오프셋·안전 여유를 Node/Unity에서 맞춘다.

사용자가 보는 방의 모델만 로딩한다. 다른 방에 있는 관람객은 위치·관람 번호·외형·성향·반응 이력을 유지하며 논리적으로 진행하고, 해당 방으로 이동하면 다시 보인다. 모든 방의 GLB를 동시에 로딩하지 않는다. 인원 설정은 박물관 전체0~12명이며 패널에는 현재 방 인원과 전체 인원을 구분한다. 실행을 종료했다가 다시 켰을 때 개별 손님 위치까지 복원하는 영구 세이브는 아니다.

문 연결은 방 경계 전환이다. 서로 다른 방이 하나의 연속된 큰 공간에 물리적으로 붙는 구조는 아니다. 기존 Page Up/Down·방 이동 버튼도 유지한다. 실제 문 위치의 접근 이동도 지정한 입구/출구를 따른다. 방별 벽 색과 기존 전시품/대사 파일은 유지한다.

## 검증 방법

- `node tools/test-navigation.mjs`: 미로·문/순서 계약·인증·동시수정·백업·막힌 통로 거절, Unity 공통 fixture 생성.
- `powershell.exe -File tools/test-navigation-player.ps1`: 생성된 격리 fixture에서 실제 Player의 순차 감상·방 연결·관람객 퇴장·카메라 방 전환 시 손님 유지 검사.
- 기존 등록/배치/테마/반응 API 및 관람객/격자/대사 Player 회귀를 함께 확인한다. 실제 Quest 검증은 별도다.

실제 검증 결과와 미해결 항목은 STATUS/WORKLOG에 기록한다. 개인 Archive 원문·모델·관람 이미지·검증 사본은 공개 Git에 포함하지 않는다.

## 플레이어의 박물관 입장·퇴장 (ROUTE-002)

첫 방 입구로 나가면 입장 안내, 마지막 방 출구로 나가면 관람 종료 안내를 표시한다. **박물관 입장/처음부터 다시 관람**은 첫 방으로, **전시실로 돌아가기**는 현재 방의 안전한 입구 위치로 이동한다. 방이 하나여도 입구와 출구를 같은 방식으로 처리한다.

모든 문 바깥에는 지면과 겹쳐 이어진 안전 바닥과 충돌 경계가 있어 방 전환 유예 중에도 아래로 떨어지지 않는다. 예외적으로 지면 아래나 허용 공간 밖에 나가면 안전 위치로 복귀하고 낙하 속도를 초기화한다. 관람객의 순차 진행과 자료는 유지된다.

현재는 작은 안전 출입 공간+입장/종료 안내 화면이다. 별도의 넓은 실외 로비·건물 외관은 후속 확장이다. 실제 Quest의 안내 화면/입출입 조작은 별도 실기기 검증이 필요하다.

`node tools/test-exit-boundary.mjs`로 단일방·네방향 문을 실제 CharacterController로 걸어 바닥 지지, 이동 유예, 연결/종료, 강제 낙하 복귀와 재입장을 검사한다.

# 순번 대기 시험판 (CROWD-001)

전시물마다 선착순 티켓과 관람 자리 하나를 관리한다. 나중에 온 손님은 통행로 옆 대기 위치에서 기다리고, 앞사람이 관람을 마친 후 별도 퇴장점으로 빠져나가야 관람 자리를 넘겨받는다. 이동 중 막히면 다른 몸을 피해 다시 길을 찾지만 티켓과 관람 순서는 유지한다. 카메라의 방 전환은 순번을 바꾸지 않으며 손님 제거는 예약을 정리한다.

2026-10-17 별도 작업 브랜치에서 미로·인접 전시물3방/6명 PC 검증 완료. 사용자 승인 후 PR20 통합·실행판 반영을 마쳤으며 Quest·대인원 성능은 미검증이다. 안전한 접근·퇴장 공간이 없는 배치에서는 강제로 통과하거나 전시물을 건너뛰지 않고 기다린다. 수용량 자동 조절은 후속 작업이다. 상세 근거는 [CROWD-001 인계](handoffs/CROWD-001.json), 다음 작업은 [분할 계획](CROWD_PLAN.md)을 따른다.

CROWD-004 정체 수정: 다음 전시물에서는 이전 전시물의 퇴장 지점을 대기 버퍼로 사용하여 입구 쪽으로 되돌아가지 않는다. 대기 손님도 막힌 선순위 손님에게 양보할 수 있다. 방마다 한 명씩 양보하고4초 내 원래 목적지 복귀를 재시도하여 양보 상태에 갇히지 않게 한다. 대기 위치는 방의 고정 배치에서 한 번만 계산한다. 검증은 docs/handoffs/CROWD-004.json 참고.
