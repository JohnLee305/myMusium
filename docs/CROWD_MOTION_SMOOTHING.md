# CROWD-006 관람객 보행 보정

관람객이 충돌 경계까지 일정한 속도로 다가간 뒤 즉시 멈추고, 양보 직후 다시 같은 자리로 돌아오면서 반복 정지하는 현상을 줄였다. 저장 맵과 목표 12명, 관람 순번은 유지한다.

- 출발·정지 가감속과 회전 중 감속을 적용한다. 걷기 애니메이션은 실제 이동 속도에 맞춘다.
- 앞사람과 가까워지면 미리 감속한다. 교차할 때 먼저 들어온 관람객과 관람을 마치고 자리를 비우는 사람을 우선한다. 기존 몸 간격 검사는 유지한다.
- 양보할 위치는 우선 통행자의 진행 경로 밖에서 고른다. 비킨 뒤 통과할 시간을 주고 복귀한다. 양보는 방당 한 명, 최대 8초로 제한한다.
- 선택적으로 실행하는 120초 실시간 측정 도구를 추가했다. 일반 실행은 측정 파일을 만들지 않는다. 측정 결과와 개인 자료는 Git에 포함하지 않는다.

## 검증 범위

개인 자료를 외부 전송하지 않고 현재 맵에서 실시간 측정한다. 자동 회귀는 동일한 벽·출입구·전시 위치를 익명 공개 샘플로 재현한다.

Windows 빌드 `logs/unity-Build-20261017-171332.log` 성공.

| 검사 | 결과 |
|---|---|
| 동일 배치 12명, 60Hz 간격, 모의 900초 | 관람 276회, 퇴장 41명; 마지막 120초 관람 39회·퇴장 6명; PASS |
| 별도 좁은 미로 6명, 0.1초 간격, 모의 600초 | 관람 30회, 퇴장 6명; 후반 진행 PASS |
| 인접 전시 대기열 12명 | 순번·몸 간격·관람 후 이동·후반 진행 PASS |
| 실제 FIFO 클래스 | 18개 검사 PASS |
| 관리·자료·동선 등 Node 전체 회귀 | 15개 묶음 PASS |

로그: `logs/deadlock-20261017-171544/`, `logs/navigation-tests-1792224800172/tour-player-6-20261017-171518.log`, `logs/queue-compact-20261017-171607/`, `logs/crowd-006-local-ci-retry.log`.

초기 수정에서 높은 프레임률의 미세한 출발 이동이 정지로 판정되어 가속이 취소되는 문제를 발견해 수정했다. 별도 미로에서 복귀한 대기자가 퇴장 경로를 다시 막는 회귀도 발견하여 양보 위치와 복귀 조건을 보완한 뒤 위 검사를 다시 통과했다. 첫 Node 실행은 Windows 임시 manifest 교체 EPERM으로 실패했고 재실행은 통과했다.

실시간 비교는 한 PC·한 배치의 한 차례 측정이다. 임의 배치 전체의 무정체 보장이나 Quest 실기기 성능 검증을 뜻하지 않는다. 정상적인 관람·차례 대기 시간은 이동 의도가 있을 때의 연속 정지와 구분한다. 처리량 증가를 목표로 한 변경은 아니다.

## 현재 저장 맵의 실제 120초 비교

수정 전 CROWD-005 진단과 최종 수정판을 같은 맵·12명·속도1에서 비교했다. 이동 의도가 있을 때 연속으로 멈춘 최대 시간이 16.01초에서 0.37초로 줄었고 양보 횟수는 12회에서 0회가 됐다. 문제가 컸던 4번 손님의 경로 설정은 33회에서 10회, 정지는 28회에서 12회였다. 관람은 양쪽 모두 23회였다. 퇴장은 1명에서 0명으로, 보행 완화에 따른 출발·회전 시간이 있으므로 처리량 향상으로 해석하지 않는다.

프레임 시간 P95는 6.99ms와 6.97ms, 관람객 처리 P95는 모두 약0.26ms였다. 최종 로그는 logs/motion-20261017-171726/summary.txt, 비교 기준은 CROWD-005의 logs/motion-20261017-165724/summary.txt다. 개인54파일 SHA256이 일치했다.
