# 방 수에 따른 자동 관람객

관리 화면의 관람객 수에서 **방 수에 맞춰 자동**을 고르고 저장한다. 기존 외형·속도·직접 지정 인원은 유지한다. 기존 설정에 mode가 없으면 수동으로 읽으므로 오래된 저장 파일도 그대로 사용할 수 있다. 자동을 끄면 저장된 수동 인원을 다시 사용한다.

자동 목표는 전시품이 있는 방당 6명, 전체 최대 120명이다. 빈 방은 목표에 더하지 않는다. 현재 3개 전시실은 목표 18명이다. 방 배치를 바꾼 뒤 관람 앱을 다시 열면 새 방 수로 계산한다. 실제 인원은 입구·각 방이 비워지는 속도에 따라 목표보다 적을 수 있다. 모든 관람객은 첫 입구에서 출발해 전시 순서대로 방문한다.

방별 입장 한도는 전시품 수와 벽을 제외한 빈 공간으로 6~12명 사이에서 정한다. 입구가 막히거나 다음 방이 가득 차면 들어가지 않는다. 대기 위치는 전시 접근로·관람 후 자리 비우기 경로·출구까지의 통로를 비운다. FIFO 순번은 유지한다. 수동 모드는 기존 전체 0~12명 한도를 유지한다.

## 나눈 작업

1. **설정·입장 정책:** 선택적인 mode=auto/manual 계약, 자동 목표, 방별 한도, 수동 전환, 저장 호환성.
2. **지속 부하 억제:** 같은 방 관람객 목록으로 충돌·양보를 검색한다. 보이지 않는 방의 수동 애니메이션 평가를 중단한다. 동적 우회 경로 계산은 프레임당 2회로 나누고 오래 미뤄진 요청부터 처리한다. 계산이 미뤄진 손님은 다음 프레임에 재시도한다. 방의 고정 통로·대기 위치 계산은 캐시한다.
3. **검증:** 현재 배치 자동 인원, 기존 12명 회귀, 전시실 6/20개 장시간 진행, 30/60/120명 실제 시간 부하 측정. 실제 시간 부하와 모의 관람 시간을 구분해 기록한다.

실제 프레임이 45FPS보다 느린 상태가 누적되면 새 입장을 잠시 쉬고 안정된 뒤 다시 받는다. 이미 입장한 사람을 갑자기 지우거나 관람 순번을 취소하지 않는다. 관람 앱의 인원 버튼은 임시 조절이고 저장은 관리 화면에서 한다.

대인원 부하 검사는 공개 샘플 방에 인원을 분산 배치하는 별도 측정이다. 정상 입장 속도를 측정한 결과와 혼동하지 않는다. 실제 앱은 첫 입구로만 점진 입장시킨다. Quest 실기기와 모든 임의 맵의 무정체·프레임 성능을 보장하는 검사는 아니다.

## 검증 중 발견하고 보완한 문제

- 동시에 많은 경로를 요청할 때 고정 순서의 손님만 계산 기회를 얻던 문제: 미뤄진 요청 순서를 기록하고 다음 프레임 재시도로 공정하게 분산했다.
- 대기자가 접근로는 비우지만 출구 방향 동선을 막던 문제: 출구까지의 고정 경로도 대기 자리 배치에서 제외했다.
- OneDrive 안의 반복 임시 파일 교체가 EPERM으로 실패하던 관리 테스트: 해당 테스트의 공개 fixture를 OS 임시 폴더에 생성한다. 제품 저장 위치와 개인 자료는 바꾸지 않는다. 이후 Node 전체 15개 묶음 통과.
