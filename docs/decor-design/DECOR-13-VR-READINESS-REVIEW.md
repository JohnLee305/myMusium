# DECOR-13 · 완료 구현의 VR 전환 검토

검토일: 2026-10-18. 정적 코드 검토이며 VR 실행·착용 검증 결과가 아니다. 검토 대상은 DECOR-01~06 통합판 및 별도 폴더 `C:/Dev/vr-museum-decor-07-20261018`의 미커밋 DECOR-07 구현이다. 아래 소스 위치는 `apps/quest-viewer/Assets/Museum/` 기준이다. 13 작업폴더에는 07이 아직 통합되지 않았으므로 07 통합 후 줄 번호를 다시 확인한다.

## 판단

아이템 계약·명령·기하·저장 코어는 재사용한다. 수정 범위는 주로 05의 카메라/UI, 06의 포인터/입력 연결, 07의 UI와 세션 수명 결합이다. 현재 PC 시험판을 VR 지원 완료로 간주할 수 없다. 아래 P1은 VR 연결 전에 해결할 차단 항목, P2는 기능 동등성/실측 검증 항목이다. 현재 PC에서 발생했다고 재현한 오류와 향후 VR 연결 시의 위험을 구분한다.

## 발견 사항과 인수 조건

### R1 · P1 · PC 카메라를 HMD에 연결하면 추적 위치와 충돌

`Runtime/Decor/UI/DecorCamera.cs:51`은 transform 위치/회전을 직접 쓴다. `DecorInputRouter.cs:50`은 이동 입력이 0이어도 Move를 호출한다. `Editor/DecorPrototypeSetup.cs:39` 및 시험 씬은 일반 Camera/DecorCamera를 만들며 XR Origin 연결이 없다.

PC 카메라는 유지하고 VR은 HMD 추적과 XR Origin 이동으로 분리한다. VR에서 F/방 전체 맞춤/휠 확대를 HMD 위치 덮어쓰기로 구현하지 않는다. 15에서 기존 PC 카메라 회귀, 16/17에서 머리를 움직이는 동안 카메라 강제이동이 없고 좌식/입식 재중심화가 되는지 확인한다.

### R2 · P1 · 화면 좌표와 PC UI에 묶인 입력 경계

`DecorEditorController.cs:33`은 Vector2 화면 좌표와 ScreenPointToRay를 요구하고, `DecorPanel.cs:105`의 UI 차단도 화면 좌표 기반이다. `DecorInputRouter.cs:24`부터 키보드/마우스만 연결하며 80~81행은 단순 활성/비활성 전환이다. 입력 소유자·추적 상실·버튼 해제 후 재진입 처리는 없다.

14에서 공통 월드 레이/입력 의도와 UI 우선 중재를 추출하고, 16에서 컨트롤러와 연결한다. PC/VR 동시 입력, 양손 중복 확정, UI 뒤 월드 선택, 추적 상실 뒤 이전 후보 확정, 누른 채 모드 전환을 각각 검증한다. 기존 관람용 VR 입력과의 충돌도 실제 앱 연결 시 별도로 검증한다.

### R3 · P1 · 바닥 배치 레이가 가림을 무시

`DecorEditorController.cs:38`부터 바닥 가구 후보는 무한 Plane 교차점으로 만든다. 소품 상판 경로(51행)와 달리 앞의 벽/가구를 첫 충돌물로 검사하지 않는다. 따라서 벽 뒤에 유효한 빈 바닥이 있으면 기하 검증을 통과하는 후보가 만들어질 수 있다. 이는 코드 경로에서 확인한 가능성이며 실제 VR 재현은 미실시다.

14의 공통 포인터 질의에서 바닥·상판 모두 가시성, 거리 한도, 레이어 정책을 적용한다. 벽/앞 가구는 차단하고 프리뷰·자기 컨트롤러의 보조 콜라이더는 명시적으로 제외한다. 벽 뒤의 빈 바닥, 가구 뒤 바닥, 보이는 상판, 범위 밖 레이, 자기 콜라이더가 포함된 사례를 검사한다. 충돌 판정과 가시성 판정은 서로 대체하지 않는다.

### R4 · P1 · UI 교체와 편집 세션 수명이 결합

`DecorPanel.cs:56,91`은 패널에 Session과 Editor를 생성한다. `DecorPrototypeSession.cs:105`는 파괴 시 저장 작성자를 해제하고, `DecorEditorController.cs:20`의 Reset/Accept는 Interaction을 새로 만든다. 이는 적용/전체 취소 경로에는 의도된 동작이지만 PC 패널을 파괴하고 VR 패널을 생성하는 전환에 재사용하면 초안·Undo와 작성자 소유권을 유지하지 못한다.

14에서 세션/Interaction/작성자 수명을 UI 수명과 분리한다. 장치 전환은 Reset/Accept/Reload를 호출하지 않고 프리뷰만 취소한다. 미저장 배치·Undo/Redo·선택·단일 작성자 잠금이 PC→VR→PC 후 유지되고 디스크 revision/저장 내용이 바뀌지 않는지 검사한다. 07 저장 포맷은 변경하지 않는다.

### R5 · P1 · 오류 복구 UI도 VR 경로 필요

`DecorPrototypeSession.cs:91`의 Problem은 월드 표시를 끄고 UI Toolkit 오버레이에 복구 버튼을 표시한다. 현재 구현에는 그 메뉴의 VR 표시/레이 입력 경로가 없다. 정상 메뉴만 VR로 옮기면 로드/활성화 실패 시 복구 조작을 잃을 수 있다.

16에서 오류/읽기 전용/전체 취소 확인도 공간 UI로 제공한다. 월드 아이템 표시 실패와 독립적인 안전한 공간·복구 패널을 유지한다. 17에서 prepare 실패, 저장 후 activate 실패, 로드 실패, 다른 작성자가 있는 경우를 실제 HMD에서 확인한다. 실패 상태에서 원본 저장을 덮어쓰지 않는 기존 계약을 유지한다.

### R6 · P2 · 키보드 전용 기능과 화면용 레이아웃

`UI/Decor/DecorPanel.uxml`에는 스포이트(I), 자유 위치(Alt), 연속 배치(Shift)의 전용 버튼이 없다. 검색은 TextField이며 가상 키보드 연결이 없다. 패널은 픽셀 기반 화면 배치다.

15/16에서 기능별 명시적 버튼/토글·현재 상태와 장치별 안내를 제공한다. VR에는 공간 패널·레이 스크롤·검색 입력/취소를 구현하고 PC 픽셀 레이아웃은 유지한다. 16 최소 패널+꽃병 착용 확인을 먼저 수행한다. 크기/거리의 초깃값과 근거는 [Meta 원칙](박물관-꾸미기-개발명세/07-Meta-원칙과인수기준.md)을 따른다. 17에서 물리 키보드 없이 전 기능 조작을 확인한다.

### R7 · P2 · 프레임 지연과 작은 물체 선택은 실측 필요

`DecorPanel.cs:257`은 명령 후 전체 아이템 표시를 파괴·재생성한다. `DecorPrototypeSession.cs:51`은 준비/저장/활성화를 동기 호출한다. `DecorPanel.cs:149`의 선택은 단일 물리 레이이며 작은 꽃병 선택 보조는 없다. 현재 PC 통과 결과는 Quest Link에서의 프레임 시간·양안 가독성·선택 성공률을 증명하지 않는다.

16/17에서 많은 아이템, 반복 이동/회전/Undo, 적용/로드, 꽃병 원거리 선택 시 CPU/GPU 프레임 시간과 할당·양안 프리뷰 가독성을 측정한다. 성능 결함으로 단정하지 않으며 측정 결과에 따라 부분 갱신/풀링/저장 단계 분리를 선택한다. Unity 객체 생성을 무조건 백그라운드로 옮기지 않는다. 선택 보조는 실제 오브젝트 크기와 가림 규칙을 유지한다.
