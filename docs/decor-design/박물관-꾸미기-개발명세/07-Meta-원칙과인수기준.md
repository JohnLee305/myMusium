# Meta 핵심 원칙과 박물관 적용·인수 기준

2026-10-18 확인 · DECOR-13 설계 보강. 아래 순서는 **우리 프로젝트의 우선순위**이며 Meta가 공식적으로 매긴 순위가 아니다. 출처 요약, 우리 설계 선택, 향후 검사 기준을 구분한다. 문서 반영은 구현·실기기 통과가 아니다.

## 1. 공식 자료와 적용 범위

- **S1** [Key considerations](https://developers.meta.com/vr/design/mr-design-guideline/) — 표시 갱신일2025-10-07. 편안함·공간 배치·피드백·빠른 체험·실기기 반복 원칙. MR/패스스루 설명 중 공통 원칙을 VR에 적용하며 현실 공간 인식 기능까지 요구하지 않는다.
- **S2** [Hands UI best practices](https://developers.meta.com/vr/design/hands-ui-best-practices/) — 표시 갱신일2026-09-24. **손 추적 입력용** 거리·목표 크기·밀도·손목 메뉴·상호작용 원칙. 컨트롤러의 공식 최소 규격으로 부르지 않는다.
- **S3** [Panels](https://developers.meta.com/vr/design/panels/) — 표시 갱신일2026-03-02. 패널 구성과 이동·크기 변경 UI 참고. Horizon OS 패널의 dp 규격을 Unity 월드 Canvas의 m/px로 그대로 복사하지 않는다.

## 3. 수치와 패널 정책 수정

S2의 손 입력 권고는 선택 영역48dp, 권장 접촉 거리에서 약22mm, 시야각 약2.5~3도, 인접 간격12mm다. 이는 손 추적 조건이다. 우리 컨트롤러 UI는 **거리와 시야각을 함께 검토하는 방법**을 채택하고 이 값을 제품 보장으로 복사하지 않는다.

기존06문서의 버튼 높이25mm는 원거리 레이의 단독 기준으로 폐기한다. 컨트롤러 시험 시작값은 패널 거리1m·높이방향 hit 영역45mm로 바꾼다. 시야각 환산은 `h=2*d*tan(theta/2)`이며1m에서2.5도는 약44mm다. 이는 기하 계산과 우리 보수적 초깃값이다. 버튼 가로 폭도 대상각을 확인하고 가로/세로 중 작은 쪽을 검사한다. 보이는 색상 칩은 작아도 주변 hit 영역이 겹치지 않아야 한다. 메뉴 폭이 부족하면 버튼을 줄이지 말고 페이지/그룹을 나눈다.

패널은 기본1m·시선보다 약간 아래에서 시작하고0.8/1.0/1.2m를 실제 검사한다. 거리 변화 시 UI와 hit 영역을 함께 조정하고 크기 상·하한을 둔다. 전시대·꽃병의 실제 모델 치수와 충돌 proxy는 확대하지 않는다. 자동 크기 조정 때문에 누르는 도중 목표가 움직이지 않게 현재 누름 동안 레이아웃을 고정한다. 이 정책의 손떨림·가독성 결과를17에서 기록한다.

간접/직접 입력을 혼용하는 손 추적은 이번 범위에 추가하지 않는다. 나중에 도입하면S2의 근거리 접촉·원거리 레이 전환과 명확한 모드 표시를 별도로 검증한다. 현재는 가까이 다가간 사용자가 패널을 편한 레이 거리로 다시 옮길 수 있게 한다. 눈 추적·핀치·손목 제스처도 필수 입력으로 만들지 않는다.

## 4. 구현 방법과 검증 Gate

1.14: M05/M06의 상태·capabilities·입력소유권·누출 차단을 공통 의도와Presenter에 정의한다.
2.15: PC 화면도 같은 상태·버튼 경로를 사용하고 기존 마우스/검색/저장 회귀를 유지한다.
3.16-A: 설치된 XRI로 최소 패널·레이 클릭·꽃병 배치·취소를 만든다. 기기에서M01~M06을 먼저 확인한다. 기기 대기 중 공통/자동 검사는 계속하되 거리·레이아웃 확정과 나머지VR메뉴 확장은 이 결과 이후 진행한다.
4.16-B: 수정된 패널을 기준으로 카탈로그·보관함·검색·적용/취소를 확장한다. 대표 정보/카탈로그/모달 화면에 M01~M08 대응표를 남긴다.
5.17: 각M항목의 합격/실패/미실행, 실제PC/Quest 구분, 기기·패널거리·hit 영역·앉기/서기·좌우손·사용자의견·수정전후를 기록한다. P0 실패/미실행이면VR완료·08진행 Gate를 열지 않는다. 실제NPC·자료이전은08에서 설계한다.

S3의 패널/공식 UI Set은 배치·이동 affordance 참고자료다. SDK 채택은 별개다. 기존 OpenXR/XRI 사용을 유지하고 원칙 반영을 이유로 Interaction SDK를 추가 설치하거나 두 입력 시스템을 동시에 활성화하지 않는다. 새 SDK가 필요한 근거가 나오면 기술검사·ADR로 먼저 판단한다.
