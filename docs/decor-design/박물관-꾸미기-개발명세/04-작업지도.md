# 작업 지도와 위임 순서

작업 단위는 작은 결과와 명확한 종료점을 기준으로 나눈다. 모든 표의 상태는 미착수다. 아래 목록은 GitHub 담당 선점 목록이 아니다.

| 작업 | 선행 | 산출물 | 위임 준비 |
|---|---|---|---|
| [DECOR-01](tasks/DECOR-01.md) | 없음 | DTO·스키마 연결·참조 검사 | 준비됨 |
| [DECOR-02](tasks/DECOR-02.md) | 01 | 명령·Undo·보관 규칙 | 선행 후 가능 |
| [DECOR-03](tasks/DECOR-03.md) | 01 | WorldStore 잠금·저장·복구 | 선행 후 가능 |
| [DECOR-04](tasks/DECOR-04.md) | 01 | 직각 배치·표면·충돌 검증 | 선행 후 가능 |
| [DECOR-05](tasks/DECOR-05.md) | 01 | 시험 씬·카메라·편집 UI 골격 | 선행 후 가능 |
| [DECOR-06](tasks/DECOR-06.md) | 02,04,05 | 선택·프리뷰·부착·회수 연결 | 선행 후 가능 |
| [DECOR-07](tasks/DECOR-07.md) | 03,06 | 한 방 시험판·저장 재실행·체감 검토 | 선행 후 가능 |
| [DECOR-08](tasks/DECOR-08.md) | 07 | 기존 자료·손님·실행 앱 연결 설계 검토 | 설계 담당의 Gate |
| [DECOR-09](tasks/DECOR-09.md) | 08 승인 | 콘텐츠 게시·카탈로그·고유 전시 계약 확장 | 세부 계약 확장 후 위임 |
| [DECOR-10](tasks/DECOR-10.md) | 09 승인 | 조명·벽/천장·재질 계약과 시험 | 세부 계약 확장 후 위임 |
| [DECOR-11](tasks/DECOR-11.md) | 08~10 | 실제 PC 관람 통합·이전·회귀 | 통합 분할 검토 후 위임 |
| [DECOR-12](tasks/DECOR-12.md) | 11 | 사용자 체감 검토·후속 우선순위 | 검토 담당 |

01~07은 첫 세로 기능의 구현 명세다. 08~12는 후속 Gate 카드이며, 큰 변경을 한 번에 구현하라는 지시가 아니다. 시제품 결과를 받은 설계 담당자가 지원 계약·하위 작업을 작성한 후 실행한다. 이것은 미정 사항을 개별 구현자에게 떠넘기지 않기 위한 경계다.

처음에는 순서대로 진행한다. 01 이후 02/03/04/05는 별도 파일 영역으로 나눌 수 있지만 병렬 실행은 사용자가 요청한 경우에만 시작하고, 동일 저장소의 담당 선점 규칙을 따른다. 먼저 끝났다는 이유로 선행 작업의 검토·통합 확인을 건너뛰지 않는다.

초기 구현자는 전체 계획을 외우지 않아도 된다. 해당 작업 카드, 03의 해당 절, fixture, 선행 인계만 읽는다. 중요한 계약 변경은 설계 담당자에게 돌리고, 정해진 계약 안의 함수 분리·지역 변수·표시 간격은 직접 결정한다.

## 검토 지점

1. 01 완료: 데이터·참조·오류 코드가 예시와 일치하는지 확인.
2. 03/04 완료: 저장 손실·충돌·좌표 규칙 검토.
3. 07 완료: 사용자에게 다섯 조작 장면을 보여주고 체감 조정.
4. 08: 실제 자료 이전·손님 정지/복원·포털 안전을 계약으로 확정.
5. 11 완료: 수정된 실제 실행판의 경로·자료 보존·회귀 확인.

경제·다층·방 공유·VR 편집은 이 작업 지도 밖이다. 첫 사용자 완성은 후속 09/10까지의 소장품·소품·조명을 실제 박물관에서 쓸 수 있는 상태이며, 07 시험판을 전체 기능 완료로 부르지 않는다.
