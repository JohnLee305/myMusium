# 첫 구현 공통 계약 — decor-slice-1

범위는 시험 방, 바닥 전시대, 상판 소품, 보관, 명령, 원자적 저장이다. 경제·고유 소장품·벽/천장 부착은 아직 스키마에 포함하지 않는다. 이 제한된 계약을 먼저 일관되게 구현한 뒤 확장한다. 실제 개인 자료의 포맷을 이 시험 계약으로 자동 변환하지 않는다.

## 1. 파일과 정본

- `contracts/edit-slice.schema.json`: JSON Schema draft-07. fixture envelope `{catalog, world}`의 형식 검사.
- 스키마 `definitions/catalog`, `definitions/world`는 런타임의 각각의 문서 구조다. envelope는 테스트 운반 형식이고 실제 저장은 world만 한다.
- `fixtures/cases.json`: 각 파일의 형식 검사 기대값과 의미 검사에서 포함해야 하는 오류 코드.
- `valid-placed.json`과 `valid-stored.json`: 두 정상 상태.
- 첫 계약은 미래 생산용 포맷과 구별되는 schemaVersion `decor-slice-1`을 사용한다. 영구 호환을 보장하는 정식 v1로 오해하지 않는다.

`ItemDefinition.id + version`이 종류의 버전 키다. `ItemInstance.id`가 소유 물건의 키다. room 목록 index·표시 이름·Unity InstanceID로 저장 참조를 만들지 않는다. 첫 계약에는 `ownedCount`, `placedCount`를 저장하지 않는다.

## 2. 좌표·표면 규칙

모든 벡터는 [X,Y,Z], 단위는 m. +Y는 위, +Z는 앞. Yaw는 Unity의 Y축 회전과 같은 방향, 저장 범위 [0,360). 360은 0으로 정규화한다. 위치·치수는 유한수이며 스키마의 크기 제한을 따른다.

room.bounds는 방 내부의 직육면체이며 yMin이 바닥이다. 가구 원점은 밑면 중심. room 위치는 방 로컬이다. parent 위치는 부모 **물건의** 로컬 좌표이며 surface 중심 기준 좌표가 아니다. 부모가 회전하면 자식의 위치·회전도 함께 변환된다.

`collision`은 아이템 로컬 중심과 크기로 표현하는 직육면체다. 렌더 모델의 AABB를 저장 때마다 다시 측정하지 않는다. 첫 시험판 yaw는 0/90/180/270만 조작할 수 있다. 계약은 임의 yaw도 표현할 수 있지만, 첫 geometry validator는 지원 밖 yaw에 `ROTATION_UNSUPPORTED`를 반환한다. 이를 정상 지원으로 통과시키지 않는다.

상판 `supports[].centerM`은 부모 원점 기준 높이와 중심, `sizeXZ`는 사용 가능한 수평 영역이다. 자식 밑면의 모서리가 전부 이 영역 안에 있어야 한다. 자식의 localPositionM.y는 상판 높이와 같아야 한다. 기준 수치 허용 오차는 0.001m다. 경계 접촉은 허용, 오차를 넘는 침투는 거절한다. 자식과 부모의 지정 표면 접촉만 면제하고 자식끼리의 겹침은 검사한다.

snap은 XZ에만 적용한다. 0.25m/0.05m 눈금은 바닥일 때 방 원점, 상판일 때 상판 centerM의 XZ를 기준으로 적용한다. 반칸 값은 원점에서 먼 쪽으로 반올림한다. 예: ±0.125를 0.25 눈금에 맞추면 ±0.25. 입력 뒤 1mm로 정규화하고 정규화 결과를 검사한다. 저장 재읽기에서 추가 snap을 적용하지 않는다.

장식은 `surfaceDecor`, 전시대·큰 가구는 `floorFurniture`다. storage에는 둘 다 올 수 있다. 설치 시 floorFurniture는 room, surfaceDecor는 parent만 허용한다. parent는 room 또는 storage에 있는 floorFurniture만 될 수 있다. 첫 버전 부착 깊이는 한 단계다.

## 3. 의미 검사 순서와 오류

형식 검사 실패 시 `SCHEMA_INVALID`를 반환하고 의미 검사에 들어가지 않는다. 이후 안정된 순서로 검사하며 오류 목록을 코드/ID 순으로 정렬한다. 한 참조가 깨졌을 때 그 참조에 의존한 충돌 계산은 건너뛰어 불필요한 파생 오류를 만들지 않는다.

| 순서 | 검사 | 코드 |
|---|---|---|
| 1 | world.catalogRevision과 catalog.revision 일치 | CATALOG_REVISION_MISMATCH |
| 2 | 정의 ID+버전, roomId, instanceId, support/variantId 중복 | DUPLICATE_DEFINITION / DUPLICATE_ROOM_ID / DUPLICATE_INSTANCE_ID / DUPLICATE_SUB_ID |
| 3 | 인스턴스 정의와 변형 존재 | DEFINITION_NOT_FOUND / VARIANT_NOT_FOUND |
| 4 | 방·부모 참조 존재, 부모 그래프 순환 | ROOM_NOT_FOUND / PARENT_NOT_FOUND / PARENT_CYCLE |
| 5 | 허용 설치 종류·깊이·표면 참조 | SURFACE_KIND_INVALID / PARENT_DEPTH_INVALID / SUPPORT_NOT_FOUND |
| 6 | 지원 회전, 바닥/상판 접촉, 상판 여유 | ROTATION_UNSUPPORTED / FLOOR_HEIGHT_INVALID / SUPPORT_HEIGHT_INVALID / SUPPORT_OVERHANG |
| 7 | 방 안 포함, 예약 영역과 충돌, 물건 충돌 | OUTSIDE_ROOM / RESERVED_ZONE_BLOCKED / ITEM_COLLISION |

저장 상태에 있는 루트는 방 경계·다른 가구와 충돌 검사에서 제외하지만 자식의 지지·서로 겹침은 검사한다. ID·정의·표면 참조도 검사한다. 예약 영역은 시험판에서 문 앞 공간을 대체하며 통로 전체 연결을 검증한 것은 아니다. 실제 길찾기는 DECOR-08 이후 별도 Gate다.

도메인 반환값은 오류 코드, primaryId, relatedIds, 선택적 roomId, 위치를 갖는다. 사용자 한글 문구는 UI에서 매핑한다. 오류 코드를 사용자 메시지로 직접 표시하지 않는다.

## 4. 명령 API

아래 타입·호출 이름을 계약으로 사용한다. 네임스페이스는 `FamilyMuseum.Decor`를 제안 기준으로 고정한다. 소스는 `Runtime/Decor/Domain`, UI는 `Runtime/Decor/UI`, 파일 I/O는 `Runtime/Decor/Storage`에 둔다. 순수 도메인은 UnityEngine을 참조하지 않는다.

```text
Validate(catalog, world) -> ValidationReport
BeginEdit(world, catalogRevision) -> EditSession
ApplyCommand(session, command) -> CommandResult
Undo(session) -> CommandResult
Redo(session) -> CommandResult
BuildSnapshot(session) -> WorldSnapshot
Commit(expectedRevision, commandBatchId, snapshot) -> CommitResult
Load(worldId) -> LoadResult
```

`ValidationReport`는 ok와 issues 배열. `CommandResult`는 accepted, resultingDraft, issues. `CommitResult`는 status(saved/alreadySaved/conflict/failed), revision, commandBatchId, diagnosticCode. LoadResult는 정상/백업복구필요/지원하지않는버전/손상 상태를 구분한다. 실패 결과를 빈 월드로 바꾸지 않는다.

명령은 kind, commandId, payload를 가진다. commandId는 세션 안에서 유일하며 동일 ID+동일 payload의 재전달은 중복 반영하지 않는다. 같은 ID에 다른 payload는 `COMMAND_ID_REUSED`다. 명령 기록은 세션 수명이며 영구 Event Sourcing을 도입하지 않는다.

| 명령 kind | payload | 결과 |
|---|---|---|
| CreateAndPlace | instanceId, definition, variantId, location | 새 물건 한 개, 검사 성공 때만 초안에 추가 |
| SetLocation | instanceId, location | 이동·회전·부착을 하나의 변경으로 처리 |
| SetVariant | instanceId, variantId | 허용 변형만 변경 |
| Store | instanceId | 대상만 storage로 변경, 자손 parent 참조 유지 |
| PlaceStored | instanceId, location | 기존 ID를 다시 설치, 새 생성 금지 |

드래그 중 프리뷰는 초안 명령 기록 밖에 둔다. 놓기 성공 때만 명령 하나를 기록한다. 프리뷰 취소는 Undo 항목을 만들지 않는다. 거절된 명령은 초안·수량·Undo/Redo를 모두 그대로 둔다. Undo 뒤 새 명령은 Redo를 비운다. 첫 시험판 명령 한도는 200개, 초과 시 가장 오래된 Undo만 제거하고 화면에 짧게 알린다. 이 값은 설정이다.

객체 생성 ID는 명령 제출 전에 발급해 Undo/Redo와 재전달에서 재사용한다. ID 생성기를 주입해 시험은 결정적으로 만들고 실제 실행은 충돌 저항 ID를 사용한다. 저장의 revision은 성공 확정 시에만 1 증가한다.

실제 ID는 `item.`/`cmd.`/`batch.` 접두사 뒤에 소문자 UUID를 붙이는 형식으로 스키마의 첫 글자·길이 제한을 만족시킨다. 테스트 ID는 fixture의 짧은 값을 사용한다. DTO 직렬화는 문화권과 무관한 숫자 형식을 사용한다.

## 5. 저장 계약

Unity WorldStore만 world를 쓴다. 콘텐츠 catalog는 읽기 전용 입력이다. 시험판에서는 fixture catalog를 그대로 사용하고 웹 서버를 띄우지 않는다.

WorldStore는 worldId의 OS 배타 파일 핸들을 보유한다. 잠금 파일 이름이나 수정 시간만 보고 소유권을 판단하지 않는다. 쓰기 잠금을 얻지 못하면 `WORLD_IN_USE`; UI는 읽기 전용 안내를 제공한다. 모든 오류 경로에서 handle을 정리한다.

Commit은 expectedRevision 확인 → 의미 검사 → 새 revision/lastCommandBatchId 설정 → 같은 디렉터리 임시 파일 쓰기/flush → 재읽기 → 기존 snapshot backup 후 원자 교체 순이다. 파일 교체 방법은 플랫폼 어댑터 한 곳에 두고 Windows 실패 주입 시험을 수행한다. 새 파일 최초 생성도 별도 검사한다.

마지막 snapshot의 lastCommandBatchId가 같은 요청이며 내용 해시도 같으면 `alreadySaved`를 반환한다. 다르면 충돌이다. 이미 다른 batch가 저장된 뒤 오래된 요청을 보내면 expectedRevision 불일치로 거절한다. 응답 유실 때문에 revision이 두 번 증가하지 않아야 한다. Commit은 부모 관계·색상·정밀 좌표를 보존하고 JSON 필드 순서에 의미를 부여하지 않는다.

중복 요청 비교의 내용은 world에서 `revision`과 `lastCommandBatchId`를 제외하고 정규화한 값이다. 객체 키를 정렬하고 숫자를 문화권 불변 형식으로 쓰며 배열 순서는 보존한다. 저장 시 새로 붙인 revision 때문에 동일 요청을 다른 내용으로 판정하지 않는다. lastCommandBatchId 재시도 판정은 expectedRevision 충돌 판정보다 먼저 수행한다. 의미상 같아도 배열 순서를 바꾼 요청은 새로운 요청으로 취급하며, UI가 재시도 때 payload를 다시 생성하지 않고 원본 batch를 재전달한다.

최소 백업은 직전 정상본 1개, 설계 기본안은 최근 5개. 복구는 사용자에게 알려 확인된 정상본을 새 revision으로 복원한다. 손상된 최신본을 자동 덮어쓰지 않는다. 부하·보존 개수의 최종값은 후속 설정으로 둔다.

## 6. 표현과 데이터의 분리

Unity 오브젝트는 instanceId를 태그로 갖고 DTO에서 생성한다. UI 선택 상태·카메라·윤곽·미리보기·목록 스크롤은 world에 저장하지 않는다. 선택물이 사라지면 선택을 해제하고 뒤의 다른 오브젝트로 자동 전이하지 않는다.

박물관 앱 활성화 전에는 준비된 런타임을 만든다. 디스크 저장 성공 후 화면 전환 실패는 `saved-but-not-activated`로 구분한다. 이 상태에서는 기존 메모리와 다른 디스크 상태로 관람을 재개하지 않는다. 시험판은 해당 snapshot 재로딩 버튼을 제공하고, 실제 손님 복원은 DECOR-08에서 확정한다.

## 7. 변경 승인 경계

형식·ID·수량·저장 소유자·parent 좌표 의미 변경은 계약 변경이다. 담당자는 별도 패치 제안과 영향 fixture를 남기고 임의로 수정을 확장하지 않는다. UI 위치·텍스트·색상·카메라 속도는 명세의 경험을 유지하는 범위에서 담당자가 조정하고 인계에 기록한다.

스키마 파일 검증은 도메인 기능 검증이 아니다. fixtures/cases.json에서 schemaValid=true인 오류 사례들은 미래 의미 검사기가 거절해야 한다. 아직 그 검사기가 만들어지지 않은 것을 ‘시험 통과’로 쓰지 않는다.
