# 심즈식 박물관 꾸미기 — 구현 위임 명세

2026-10-17 · 기준안 1.0 · 설계 담당자가 정한 기본값 / 구현 미착수

사용자는 심즈 4 건축 모드의 즐거움을 모태로 삼고, 세부 기본값은 설계 담당자가 결정한 뒤 결과를 보며 수정하기를 요청했다. 이 묶음은 그 요청을 실제 구현 작업으로 나눈다. 사용자에게 모든 세부사항을 먼저 묻지 않는다.

## 목표 경험

방을 내려다보며 목록에서 물건을 골라 놓는다. 색을 바꾸고 같은 물건을 추가하고, 전시대 위에 작은 꽃병을 올린다. 마음에 들지 않으면 되돌리고, 물건은 보관함에 넣어 다른 방에서 다시 쓴다. 관람으로 돌아가 내가 꾸민 공간을 걸어본다. 각 방은 문으로 이동하는 독립된 이공간이다.

심즈의 공식 자료에서 확인한 목록·검색·보관함·선택/스포이트/디자인 도구·Undo와 벽 단면 보기 경험을 참고한다. 아래 단축키·수치·레이아웃·저장 구조는 이 박물관을 위해 정한 기본값이며 심즈 4의 정확한 복제나 내부 구조 설명이 아니다. [EA 공식 매뉴얼](https://eaassets-a.akamaihd.net/eahelp/manuals/the-sims-4-xbox-one-na.pdf)

## 정본과 변경 규칙

이 묶음은 상위 아키텍처의 선택지를 구체화한다. 중복 내용에서는 이 묶음의 기본값을 따른다. 첫 구현 범위의 데이터 형식은 `contracts/edit-slice.schema.json`, 관계 규칙은 03-공통계약이 정본이다. 스키마는 바닥 가구·상판 소품의 첫 세로 기능만 다룬다. 벽·천장·조명·소장품 연결·경제의 저장 형식까지 완성됐다고 간주하지 않는다.

사용자가 실제 화면에서 수정해도 되는 값과 설계 검토가 필요한 계약을 구분한다. UI 색·간격·카메라 속도·맞춤 기본값은 설정으로 조정한다. ID·소유 수량·원본 보호·저장 트랜잭션·고유 소장품 정책은 작업 담당자가 임의로 바꾸지 않는다.

작업별 파일 위치는 활성 저장소에서의 **예정 경로**다. 이 폴더는 DECOR-000으로 등록한 설계 산출물이다. 등록/병합 상태는 해당 인계와 PR을 확인한다. 게임 기능은 아직 미구현이다. 실제 구현 시작 시 저장소의 담당 선점·전용 작업폴더·Git Gate·검토/통합 규칙을 적용한다.

## 구현 상태

- 제품 기본안·화면/조작·첫 데이터 계약·작업 카드: 작성.
- JSON fixture와 스키마: 파일 형식 검증 결과는 `검증기록.md` 참조.
- C# 규칙 검사·Unity UI·편집 기능·실제 저장: 미구현.
- PC 조작감·Quest·성능: 미검증.
- 사용자 모델·소장품·실행 앱: 이 작업에서 변경하지 않음.

첫 목표는 **시험 방에서 전시대와 꽃병을 놓고, 함께 옮기고, 회수하고, 되돌리고, 저장 후 복원**하는 것이다. 기존 관람 앱에 적용하기 전까지 개인 자료를 사용하지 않는다.

## 시작할 작업

`DECOR-01`부터 진행한다. 01→02→03은 계약/순수 로직/저장의 기반이며, 04~07에서 보이는 시험판을 만든다. 각 작업 완료 시 인계 파일로 실제 검증을 남긴다. 08은 기존 앱·관람객 연결의 설계 검토 지점이고, 09 이후는 확장 계약을 검토한 뒤 착수한다.

화면 수치는 첫 기본안이다. 실제 느낌은 07의 짧은 사용자 체험에서 확인한다. 사용자가 상세 조작을 결정하지 않았다는 이유로 첫 시제품을 중단하지 않는다.
