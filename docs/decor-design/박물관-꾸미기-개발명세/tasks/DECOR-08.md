# DECOR-08 · 실제 앱 연결 설계 Gate

상태: 미착수. 이 카드는 작업 선점이나 실행 승인을 대신하지 않는다. 실제 저장소 AGENTS 및 담당 Gate를 먼저 따른다.

## 선행과 읽기

- 선행: DECOR-07 결과 확인
- 읽기: 상위 아키텍처 10~15장, 실제 GalleryDisplay/TourNavigation/TourVisitors와 최신 handoff
- 공통 규칙: ../05-인계와검토.md. 관련 카드·계약·선행 인계만 우선 읽고 과거 전체 로그를 다시 읽지 않는다.

## 수정 예정 영역

- `docs/design/DECOR-INTEGRATION.md`
- `docs/decisions/새로운-꾸미기-통합-ADR.md`
- `docs/handoffs/DECOR-08.json`

새 파일 이름은 기준안이다. 충돌하는 기존 파일이 있으면 내용을 보존하고 인계에 알린다. 공유 DTO를 임의로 변경하지 않는다.

## 구현 또는 설계할 내용

1. 현재 활성 코드와 담당 현황을 다시 읽고 DTO 연결 지점·클래스별 책임을 확정한다.
2. LegacyReader가 기존 좌표·문·명판·반응·휴지통을 보존하는 완전한 변환 표와 fixture를 작성한다.
3. 관람객 전체 정지·대기열 복원·회수된 전시 처리·안전 위치 검사·타이머를 정확한 상태 전이로 명세한다.
4. world commit 이후 실행 활성화 실패 복구와 웹 구배치 API 차단 순서를 정한다.
5. 구현 가능한 하위 카드로 분할하며 개인 자료 이전 순서와 롤백 Gate를 포함한다.

## 합격 기준

- 누가 어떤 파일을 쓰는지 모든 기존 mutation API를 포함한 책임표.
- 전시 순서/좌표/모델 scale/테마/고유 ID/반응 보존의 입력·기대 출력 fixture.
- 중단 시점별 디스크·메모리·손님 상태 표.
- 설계 검토자가 승인한 하위 작업 목록과 수정 파일 범위.

검사 도구 이름은 예정이며 현재 존재/통과를 주장하지 않는다. 구현 담당자가 실행 가능한 검사와 재현 절차를 함께 제공한다. 순수 로직 검사는 Unity 전체 빌드 없이 실행 가능하게 하고, UI/실행 검사는 실제 Player에서 확인한다.

## 제외 범위

이 카드만으로 production 통합 구현 시작 금지. 설계 검토 결과를 먼저 확정.
