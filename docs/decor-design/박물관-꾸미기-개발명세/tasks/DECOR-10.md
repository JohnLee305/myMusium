# DECOR-10 · 조명·벽·천장·마감 확장 Gate

상태: 미착수. 이 카드는 작업 선점이나 실행 승인을 대신하지 않는다. 실제 저장소 AGENTS 및 담당 Gate를 먼저 따른다.

## 선행과 읽기

- 선행: DECOR-09와 공간 계약 정합 확인
- 읽기: 상위 아키텍처 7~9,16장, 02-화면과조작
- 공통 규칙: ../05-인계와검토.md. 관련 카드·계약·선행 인계만 우선 읽고 과거 전체 로그를 다시 읽지 않는다.

## 수정 예정 영역

- `docs/design/DECOR-SURFACES-LIGHTING.md`
- `contracts/decor/표면-광원-schema.json`
- `tests/fixtures/decor-lighting/*`

새 파일 이름은 기준안이다. 충돌하는 기존 파일이 있으면 내용을 보존하고 인계에 알린다. 공유 DTO를 임의로 변경하지 않는다.

## 구현 또는 설계할 내용

1. wall/ceiling 참조, 부착 로컬 좌표, support 제거 영향, 표면 마감 데이터를 확정한다.
2. 조명 정의·개체 설정·품질 프로파일을 분리한다. 밝기 단위와 실제 사용 렌더러의 지원 범위를 확인한다.
3. 천장 편집 보기·벽 개구부·낮은 조명 통행 검사를 명세한다.
4. 가구·광원 조합 benchmark를 정하고 결과로 지원 수치·그림자 기본값을 확정한다.
5. 벽 부착/천장/조명 조작/마감·성능의 작은 구현 카드로 분할한다.

## 합격 기준

- 벽등 이동·벽 삭제·천장 높이 변경의 명확한 처리.
- 저장 광원 설정과 성능으로 제한된 실제 활성 광원 구분.
- 밝기·색 변경이 불필요한 길찾기 재계산을 일으키지 않음.
- 후속 시험 수치와 구현자별 명확한 범위.

검사 도구 이름은 예정이며 현재 존재/통과를 주장하지 않는다. 구현 담당자가 실행 가능한 검사와 재현 절차를 함께 제공한다. 순수 로직 검사는 Unity 전체 빌드 없이 실행 가능하게 하고, UI/실행 검사는 실제 Player에서 확인한다.

## 제외 범위

매번 전체 bake, 다층·곡면벽·임의 건물 연결, 실측 전 성능 보장.

## 인계와 다음 행동

저장소 규약의 docs/handoffs/DECOR-10.json에 변경 파일·실제 검사·실패·미검증·계약 변경 여부를 기록한다. 승인된 표면·조명 하위 구현과 성능 검증.

## PC·VR 동등 지원 개정

[공통 조작 계약](../06-PC-VR-공통조작.md)과 DECOR-17 검증 인계를 읽는다.08의 선행은07 및17 검토 완료다. 이후 카드는 그 계약을 이어받는다. 모든 신규 도구는 PC 화면과 VR 공간 메뉴에서 같은 명령·저장·오류처리 경로를 사용한다.08은 관람용/편집용 입력 소유권과 양쪽 모드의 진입·퇴장·실패복구 책임표를 포함한다.09/10은 소장품/조명/마감의 양쪽 UI·컨트롤러 경로를 하위 카드에 넣는다.11/12는 실제 PC 편집→VR 재실행/수정→PC 재확인과 양쪽 사용자검토를 수행한다. Quest 미검증을 남긴 채 PC·VR 통합 완료라고 기록하지 않는다.
