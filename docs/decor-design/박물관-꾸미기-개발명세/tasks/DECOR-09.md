# DECOR-09 · 콘텐츠·고유 전시 확장 Gate

상태: 미착수. 이 카드는 작업 선점이나 실행 승인을 대신하지 않는다. 실제 저장소 AGENTS 및 담당 Gate를 먼저 따른다.

## 선행과 읽기

- 선행: DECOR-08 계약 확인
- 읽기: 상위 아키텍처 5~6,11,15장
- 공통 규칙: ../05-인계와검토.md. 관련 카드·계약·선행 인계만 우선 읽고 과거 전체 로그를 다시 읽지 않는다.

## 수정 예정 영역

- `docs/design/DECOR-CONTENT.md`
- `contracts/decor/정식-확장-schema.json`
- `tests/fixtures/decor-content/*`

새 파일 이름은 기준안이다. 충돌하는 기존 파일이 있으면 내용을 보존하고 인계에 알린다. 공유 DTO를 임의로 변경하지 않는다.

## 구현 또는 설계할 내용

1. 에셋·정의 버전 게시와 immutable 파일·catalog 포인터 계약을 확정한다.
2. ArtifactBinding, 독립 전시 호스트, 명판, 보관된 소장품 연결, 고유 중복 금지의 스키마를 작성한다.
3. 등록 UI의 역할 선택·태그·치수·원점·부착면·충돌 외곽 설정을 화면 단위로 정의한다.
4. 기존 mutable 파일과 새 콘텐츠 게시의 전환·재읽기·퇴역 규칙을 fixture로 확정한다.
5. 등록/카탈로그/고유 연결/이전의 하위 구현 카드로 나눈다.

## 합격 기준

- 가상 소장품 1개를 두 호스트에 연결할 때 거절하는 계약.
- 부모 보관 중 연결 유지, 다시 설치해 동일 설명·반응 연결.
- 정의 새 버전 게시 중 편집 세션의 기존 버전 읽기 유지.
- API마다 입력·출력·오류·작성자·하위 담당 범위 명시.

검사 도구 이름은 예정이며 현재 존재/통과를 주장하지 않는다. 구현 담당자가 실행 가능한 검사와 재현 절차를 함께 제공한다. 순수 로직 검사는 Unity 전체 빌드 없이 실행 가능하게 하고, UI/실행 검사는 실제 Player에서 확인한다.

## 제외 범위

운영 경제·외부 업로드·개인 소장품 공개. 계약 미완성 상태로 하위 구현자에게 판단 위임 금지.

## 인계와 다음 행동
