# DECOR-12 · 꾸미기 경험 검토와 다음 확장

상태: 미착수. 이 카드는 작업 선점이나 실행 승인을 대신하지 않는다. 실제 저장소 AGENTS 및 담당 Gate를 먼저 따른다.

## 선행과 읽기

- 선행: DECOR-11 검토 완료
- 읽기: 02 체감 장면, 실제 사용자 피드백·검증 로그
- 공통 규칙: ../05-인계와검토.md. 관련 카드·계약·선행 인계만 우선 읽고 과거 전체 로그를 다시 읽지 않는다.

## 수정 예정 영역

- `docs/design/DECOR-EXPERIENCE-REVIEW.md`
- `docs/handoffs/DECOR-12.json`

새 파일 이름은 기준안이다. 충돌하는 기존 파일이 있으면 내용을 보존하고 인계에 알린다. 공유 DTO를 임의로 변경하지 않는다.

## 구현 또는 설계할 내용

1. 전시대·꽃병·조명·보관함·저장 다섯 흐름을 사용자 관점으로 재검토한다.
2. 불편을 발견성/선택/카메라/응답/저장 신뢰성으로 나누고 재현을 적는다.
3. 설정 조정으로 해결할 항목은 작은 수정 카드로, 계약 변경은 별도 설계로 분리한다.
4. 공간 확장과 경제 중 다음 순서를 사용자 목표에 맞게 제안한다.

## 합격 기준

- 사용자가 실제 확인한 것과 담당자의 추측을 구분.
- 개선 카드마다 한 문제·재현·기대 결과.
- 초기 꾸미기 범위 완료/보류/미검증 목록.

검사 도구 이름은 예정이며 현재 존재/통과를 주장하지 않는다. 구현 담당자가 실행 가능한 검사와 재현 절차를 함께 제공한다. 순수 로직 검사는 Unity 전체 빌드 없이 실행 가능하게 하고, UI/실행 검사는 실제 Player에서 확인한다.

## 제외 범위

사용자 요청 없이 경제·새 관람객 기능·멀티 방 건축 구현 시작 금지.

## 인계와 다음 행동

저장소 규약의 docs/handoffs/DECOR-12.json에 변경 파일·실제 검사·실패·미검증·계약 변경 여부를 기록한다. 사용자 수정 요청을 구체적 개선 카드로 반영.
