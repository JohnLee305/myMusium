# 작업 인계와 검토 규칙

## 구현 담당에게 전달할 요청

다음 문구에서 작업 ID와 경로만 채워 사용한다. 원문 사용자 요청을 대체하는 숨은 지시가 아니라 작업 범위를 분명히 하는 인계다.

```text
DECOR-XX 작업을 구현해 주세요.

활성 저장소 AGENTS.md와 실제 담당 현황을 확인하고 해당 작업을 선점하세요.
이 설계 묶음의 tasks/DECOR-XX.md, 03-공통계약.md에서 지정한 절,
관련 fixture와 선행 작업 인계를 읽으세요.

작업 카드의 산출물과 합격 기준만 구현하세요.
저장 스키마·아이템 ID·원본 자료·공통 모듈 경계를 임의로 바꾸지 마세요.
계약 충돌이 생기면 최소 재현과 변경 제안만 기록하고 영향을 받지 않는 작업은 계속하세요.
사용자에게 미세한 구현 선택을 반복해서 묻지 말고 명세 기본값을 사용하세요.

완료 시 변경 파일, 실제 검사와 결과, 미검증 항목, 알려진 문제,
다음 작업을 지정된 인계 파일에 남기세요.
개인 자료 이전·실행판 교체·통합은 저장소의 승인/검증 규칙을 따르세요.
```

## 인계에 꼭 남길 내용

저장소 `docs/handoffs/DECOR-XX.json`의 기존 규약을 따른다. 이 설계가 저장소 handoff schema를 임의로 교체하지 않는다.

- 실제 시작·끝 커밋과 작업 브랜치, 전용 작업폴더.
- 수정 파일과 노출 인터페이스, 계약 변경 여부.
- 실행한 검사 명령/fixture·결과·로그 위치. 코드만 읽은 확인과 실행 시험을 구분.
- 사용자에게 보여줄 결과와 조작 순서.
- 실패·미검증·계약 의문점 및 재현 절차.
- PR 미작성/작성/병합/실행판 반영 상태.
- 다음 담당이 읽을 최소 파일과 한 가지 다음 행동.

‘구현 완료’와 ‘통합 완료’, ‘PC 모의시험’과 ‘실제 마우스 조작’, ‘PC’와 ‘Quest’를 구분한다.

## 설계 검토가 필요한 변경

ID 재발급, 부모 좌표의 의미 변경, 새 저장 정본, 두 프로세스의 같은 파일 쓰기, 원본 모델 수정, 재고 수량 중복 저장, 정의 버전 자동 교체, 고유 소장품 복제, 이전 자료 반올림, 승인 없는 대규모 파일 이동.

이 경우 전체 작업을 무조건 중단하는 대신 해당 변경이 필요한 작은 재현, 영향을 받는 계약과 fixture, 최소 대안을 적는다. 다른 독립 합격 항목은 진행한다.

## 검토 담당의 확인

1. 카드 밖 기능이 들어갔는가? 필요하면 분리한다.
2. 거절·취소 때 상태가 바뀌지 않는가?
3. 저장된 개체 ID와 부모 관계가 재실행 뒤 같은가?
4. fixture를 통과시키기 위해 규칙을 약화하지 않았는가?
5. UI로 손쉽게 고칠 문제를 저장 구조 변경으로 해결하지 않았는가?
6. 검증되지 않은 기능을 완료라고 기록하지 않았는가?

이 문서는 구현 작업의 위임을 준비한다. 모델을 자동 실행하거나 다른 채팅에 요청을 보내는 자동화는 설정하지 않는다.

## PC·VR 동등 지원 인계

13~17은07 뒤,08 앞에 실행한다. [공통 조작 계약](06-PC-VR-공통조작.md)을 모든 입력/UI 작업의 필수 읽기로 추가한다. 각 카드 구현→자동검사→실제 표시/사용자검토→해당 통합을 거친 후 다음 카드로 진행한다. 모든 신규 편집 기능은 공통 의도와 PC/VR UI 양쪽 경로·오류 상태·접근 가능한 버튼을 명세한다.

인계에는 기능별 PC 자동/실제 마우스, XR 모의/실제 Quest Link 결과를 별도 열로 기록한다. HMD/컨트롤러·좌우손·전환·추적상실·UI 가림·한글입력·피로·프레임 측정 근거를 남긴다. 장비 착용이 필요하면 사용자께 요청하면서 독립 문서/자동검사는 계속한다. XR 에뮬레이션이나 PC 미러만 보고 VR 완료로 기록하지 않는다. 수동검증이 남으면17은 완료가 아니다.

[Meta 공식 원칙의 우선순위·적용·인수기준](07-Meta-원칙과인수기준.md)을 따른다. 편안함·공간고정·거리/시야각·분명한피드백·일관성·빠른첫체험을 기준으로16최소시제품의조기착용검토를먼저진행한다.17은자동/실기기·앉기/서기·수치출처를나눠기록한다. P0미해결/미실행은VR완료및08진행을막는다. 새SDK설치는이문서개정범위가아니다.
