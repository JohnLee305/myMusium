# 박물관 내부 꾸미기 설계 초안

> 후속 설계: [박물관 아이템 관리와 내부 꾸미기 아키텍처](박물관-아이템과-꾸미기-아키텍처.md). 2026-10-17 대화에서 방을 독립된 이공간으로 유지하기로 정했으며, 소품용 5cm 맞춤·표면 부착·아이템 관리·저장 책임·개발 단계를 후속 문서에 구체화했다. 아래 v0.1의 연속 건물 가능성과 미확정 항목은 초기 논의 기록이다. 최신 설계 검토는 후속 문서를 기준으로 한다.

작성: 2026-10-17 · 검토용 v0.1 · 구현 및 확정된 ADR 아님

## 1. 사용자 방향과 설계 범위

사용자 방향: 당분간 관람객 기능 확대보다 박물관의 완성도를 높인다. 웹 관리 화면은 소장품·에셋 등록에 집중하고, 공간 배치와 꾸미기는 박물관 안에서 한다. 장기적으로 관람료 수입 → 아이템 해금 → 자유 배치와 공간 확장을 연결한다. 먼저 설계를 면밀히 검토한다.

이 문서의 UI, 단계, 데이터 구조, 정책은 제안이다. 입장료, 가격, 해금 조건, 건축 단위와 실제 배치 간격은 아직 결정하지 않았다. 이번 작업은 현재 문서에 근거한 설계 검토이며, 코드 검사·실행·성능시험·기능 변경은 수행하지 않았다.

## 2. 현행 구조에서 확인한 제약

참고: 활성 소스 C:/Dev/vr-museum-sync-20261016의 docs/PROJECT_STATE.json, ARCHIVE.md, ORDERED_TOUR.md, CROWD_PLAN.md.

- 방은 6×5 셀, 16.4×19m 구조다. 전시품 배정과 cells가 manifest에 함께 저장된다.
- 현재 계약은 전시품마다 정확히 한 방을 요구한다. 등록 후 보관만 하는 소장품은 별도의 호환 설계가 필요하다.
- 방별 입구·출구와 관람 순서가 있으며, 방들은 순차적으로 연결된다. 연결문은 실제 연속 건물의 문이 아닌 방 전환 경계다.
- 동선 문서에는 0.4m 탐색 간격과 전시품 앞 0.8m 관람 위치가 명시되어 있다. 자유 회전에서는 관람 위치도 전시품 방향과 함께 변해야 한다.
- 대기와 퇴장 위치는 기존 고정 배치를 전제로 계산한다. 물건만 옮기면 기존 예약·경로가 유효하지 않게 될 수 있다.
- 현재 방의 모델만 표시하고 다른 방의 관람객은 논리적으로 진행한다. 연속된 전체 건물 표현은 로딩 구조까지 변경하는 별도 설계다.
- 기존 저장은 revision 충돌 검사, 백업, 원자적 교체를 사용한다. 새 편집기도 이 보호를 이어받는다.

이 제약은 기존 구현을 폐기해야 한다는 뜻이 아니다. 격자 편집의 좌표·장애물 계산을 일반화하고, 읽기 호환 계층으로 기존 배치를 보존하는 방향을 우선 검토한다.

## 3. 사용자 경험

PC 꾸미기를 먼저 설계하고 기존 PC/Quest 관람을 유지한다. VR 꾸미기는 입력·가독성·피로도를 따로 검증한 후 확장한다.

### 기본 흐름

박물관 관람 → 꾸미기 진입 → 카탈로그에서 선택 → 미리보기 배치 → 이동·회전·교체 → 적용 후 관람 재개.

꾸미기 화면은 다음 요소로 구성한다.

- 중앙: 위에서 비스듬히 내려다보는 방. 카메라 이동·회전·확대와 선택한 물건 중심 맞추기.
- 하단: 소장품 / 전시대·진열장 / 조명 / 가구·장식 / 벽·바닥 카탈로그.
- 선택 도구: 이동, 회전, 회수, 장식 복제, 전시품 연결·교체.
- 상단: 방 선택, 되돌리기·다시 실행, 적용, 편집 취소.
- 피드백: 놓을 수 있는 위치와 막히는 이유를 색상과 문구로 함께 표시.

카탈로그에서 선택한 직후에는 반투명 미리보기만 생성한다. 배치 확정 전에는 저장·재고·자금을 변경하지 않는다. Esc는 현재 조작 취소 → 선택 해제 순으로 작동하며, 모드 종료에는 미적용 변경 확인을 제공한다.

### 배치 규칙

좌표는 미터, 방 로컬 기준을 사용한다. 작은 격자 맞춤과 자유 이동을 함께 제공하되 간격은 시제품에서 결정한다. 회전도 각도 맞춤과 자유 회전을 고려한다.

초기에는 바닥 위 이동과 수직축 회전을 지원한다. 임의 높이·기울기·물건 쌓기는 제외한다. 전시대 위 소장품과 벽걸이는 전용 부착점으로 확장한다. 크기 조절은 아이템별 허용 여부·범위를 사용하고 소장품 원본 scale을 덮어쓰지 않는다.

선택하지 않은 벽·천장이 시야를 가리는 문제는 편집용 숨김/단면 표시로 해결한다. 가구 선택과 카메라 조작이 충돌하지 않도록 입력 규칙을 별도로 명세한다.

## 4. 서로 다른 데이터의 책임

| 구분 | 저장 내용 | 원칙 |
|---|---|---|
| 소장품/에셋 | 이름·설명·모델·출처·반응, 에셋 정의 | 관리 화면에서 등록·수정 |
| 배치 | 방·벽·문·아이템 인스턴스·위치·회전·전시 연결 | 박물관 내부 편집 |
| 운영 진행 | 자금·해금·구매 수량·수입 처리 | 미래 경제 시스템 |
| 일시 편집 | 선택·미리보기·미적용 명령·되돌리기 | 편집 세션, 확정 저장과 구분 |
| 실행 상태 | 손님·경로·대기 예약·임시 관람 복사본 | 배치/영구 소장품과 분리 |

위치는 모델 파일을 수정하지 않고 배치 인스턴스에 저장한다. 각 인스턴스는 안정적인 ID와 정의 ID를 가지며, 전시대에는 선택적으로 소장품 ID를 연결한다. 소장품과 전시대의 연결은 이동·회전 시 함께 변환된다.

회수는 인스턴스의 전시 해제이며 원본 삭제가 아니다. 장식 복제와 소장품 중복 전시는 별개 정책이다. 초기 제안은 소장품 하나당 전시 연결 한 개이며, 중복 전시는 명시적으로 허용하기 전까지 막는다.

관리 화면에서 사용 중인 에셋을 제거하면 영향을 보여 주고 거절하거나 참조 해제 절차를 거친다. 모델 교체로 외곽 크기가 바뀌면 기존 배치를 재검사하며 조용히 물건을 이동시키지 않는다.

## 5. 저장·기존 배치 호환

추천은 소장품 목록과 배치 문서의 분리다. 파일명·스키마는 별도 ADR과 유효/무효 fixture 검토 후 확정한다.

1. 기존 셀 번호를 기존과 같은 좌표로 읽고 기본 전시대 인스턴스로 표현한다. 읽기만으로 원본을 바꾸지 않는다.
2. 첫 명시적 전환에서 기존 manifest와 관련 설정을 백업하고, 모든 소장품 연결·문·테마·관람 순서를 보존한다.
3. 전환 후 방 배치의 정본은 한 곳으로 둔다. 웹 격자와 내부 자유 좌표를 동시에 쓰게 두지 않는다.
4. 기존 웹 배치는 전환 전까지 유지한다. 전환 후에는 읽기 안내 또는 동일한 배치 서비스로 연결하고, 오래된 격자 API의 덮어쓰기는 서버에서도 차단한다.
5. 저장은 revision 확인 → 전체 검사 → 임시 저장 → 원자적 교체 → 성공 응답 순으로 수행한다. 실패 시 마지막 정상 저장과 편집 초안을 보존한다.
6. 여러 파일 변경이 필요한 마이그레이션은 단일 파일 rename만으로 원자성을 주장하지 않는다. 버전 디렉터리와 활성 포인터 또는 복구 가능한 트랜잭션을 비교 설계한다.

운영 진행과 배치를 함께 바꿀 경제 단계에서는 구매·설치·취소가 중복 차감 없이 한 번만 확정되도록 거래 ID와 복구 계약이 필요하다. 경제 없이 시작하더라도 이 경계를 인터페이스에 남긴다.

## 6. 충돌·통로·관람객

시각 모델과 배치 판정용 footprint를 분리한다. 자유 회전한 가구는 회전된 외곽/점유 영역으로 검사한다. 벽 부착, 바닥, 전시대 위 부착은 서로 다른 표면 규칙을 사용한다.

| 판정 | 처리 제안 |
|---|---|
| 방 밖, 벽 관통, 호환 안 되는 표면 | 배치 거절 |
| 주요 물체 충돌, 출입구 안전 영역 침범 | 배치 거절 |
| 입구에서 출구 또는 필수 관람 위치까지 도달 불가 | 최종 적용 거절 |
| 너무 좁은 대기 공간, 혼잡 가능성 | 경고 또는 최소 기준 미달 거절; 기준은 실측 후 확정 |
| 순수 장식의 의도된 접촉 | 종류별 허용 규칙 적용 |

미리보기에서는 주변 충돌을 가볍게 검사하고, 적용 직전에 전체 연결성과 동선을 검사한다. 통로 폭과 관람 여유 수치는 실제 캐릭터 크기·회피 방식으로 정하며 임의로 확정하지 않는다.

초기 추천은 꾸미는 동안 박물관 전체 논리 시간을 정지하는 방식이다. 새 입장·관람·퇴장·미래 수입도 멈춰, 보이지 않는 방에서 시간이 진행되는 혼선을 피한다. 손님을 삭제할 필요는 없다.

적용 시 새 배치와 경로 계산을 준비한 뒤 교체한다. 변경된 목적지의 예약을 정리하고 관람/대기/퇴장 위치를 재계산한다. 물건 아래에 있던 손님과 플레이어는 유효한 안전 위치로 옮기고 사유를 알린다. 방 ID와 손님 ID는 유지한다. 실패 시 기존 배치·예약·정지 시점으로 복구한 후 사용자가 수정할 수 있게 한다. 이 복구가 보장되지 않으면 초기 시제품에서는 관람객 없는 별도 편집 환경으로 범위를 제한한다.

VR 물건 잡기 중에는 꾸미기 진입 전에 복사본을 정상 복귀시킨다. 방 전환·종료·저장 요청 중 모드 재진입을 막는 상태 전이가 필요하다.

## 7. 공간 확장의 두 단계

물건 자유 배치와 건축은 사용자 경험을 연결하되 구현 범위를 분리한다.

- 초기: 현재 방 크기·문 연결을 유지하며 물건을 자유 배치한다. 방별 보기와 벽 숨김을 제공한다.
- 중간: 직사각형 방 크기 조절, 벽·바닥 마감, 문 이동을 추가한다. 축소 시 밖으로 밀려나는 물건을 미리 표시하며 무단 회수하지 않는다.
- 장기: 벽 그리기·지우기, 여러 방 연결, 공간 구매·확장. 방 그래프, 문 양끝 연결, 연속 관람/로딩, 방 경계 감지와 관람객 시뮬레이션을 다시 설계한다.

장기 목표가 심즈식 연속 건물이라면 처음부터 방 ID·벽/문 ID·연결 관계를 안정적으로 정의한다. 다만 현재 화면만 바꿔 연속 건물을 구현할 수 있다고 가정하지 않는다. 건축 단계 전에 작은 두 방 연속 공간 시제품으로 로딩·동선·성능을 검증한다.

## 8. 장기 경제 계약

관람료는 카메라의 방 전환이나 입장 애니메이션이 아니라 박물관 입장 확정 이벤트에 한 번만 지급한다. 방문 ID로 중복 처리를 막으며, 불러오기·편집 종료·재입장 처리 규칙을 정한다. 내부 방 이동은 수입 이벤트가 아니다.

해금은 사용 가능 여부, 구매는 소유 수량, 배치는 설치 수량으로 구분한다. 회수·판매·환불의 차이와 편집 취소 시 자금 복구를 명세한다. 꾸미기 자체의 검증에는 무료 샌드박스를 사용하고, 경제는 선택 가능한 후속 모드로 붙이는 것을 제안한다. 이는 사용자 결정이 필요하다.

## 9. 구현 전 설계 산출물과 단계

| 단계 | 산출물·검증 | 다음 단계 조건 |
|---|---|---|
| 설계 A | 꾸미기 진입/선택/배치/취소/종료 화면 흐름, 입력표, 미확정 결정 정리 | 사용자 경험 검토 |
| 설계 B | 현행 코드 책임 지도, 저장 ADR, 호환/이전/복구 fixture, 참조·동시수정 계약 | 기존 자료 보존 방법 확인 |
| 검증 시제품 | 가상 방·가상 가구의 카메라/선택/미리보기/회전/되돌리기 | 조작감과 판정 방식 확인 |
| 첫 기능 | 기존 방 안 전시대 이동·회전·소장품 연결·저장 | 재실행 복원·동선·기존 관람 회귀 통과 |
| 꾸미기 확대 | 조명·장식·벤치·벽걸이·재질, 아이템별 부착/충돌 규칙 | 종류별 배치와 성능 확인 |
| 건축 | 방 크기·벽·문·연결·확장 | 통로·경계·방 로딩 검증 |
| 경제 | 방문료·구매·해금·진행 저장 | 중복수입/차감·취소·복구 검증 |

첫 기능에 포함할 검증: 배치 취소·되돌리기, 회전된 물건 충돌, 문 막힘 거절, 손님 근처 배치, 전시 회수, 모델 누락, 웹과 동시수정, 저장 실패, 이전 자료 전환 실패·복구, 재실행 좌표 복원, 기존 PC 관람·상세창·방 전환·VR 잡기 모의 회귀. Quest 실기기 결과는 PC 검증과 구분한다.

## 10. 먼저 검토할 결정

1. PC 꾸미기 우선에 동의하는가? 기본 시점은 위에서 비스듬히, 필요할 때 방 내부 시점으로 확인하는 흐름을 추천한다.
2. 첫 버전은 기존 방 안에서 자유 배치하고, 벽을 그리는 건축은 후속으로 분리할 것인가?
3. 편집 중 전체 시간을 정지하고 적용/취소 단위로 처리할 것인가?
4. 소장품 하나당 하나의 전시 연결로 시작할 것인가? 전시대와 물건은 별도로 선택 가능하게 할 것인가?
5. 경제 도입 후에도 자유 꾸미기 모드를 유지할 것인가?

다음 행동: 위 사용자 경험 결정을 먼저 검토하고, 화면 흐름과 상태 전이·배치 데이터 계약을 구체화한다. 활성 소스 수정, 마이그레이션, 빌드, GitHub 게시·통합은 이 초안 작성에 포함하지 않는다.
