# DECOR-07 시험 배치 저장·적용·전체 취소

DECOR-06은 PR56으로 통합했다. 이번 작업은 별도 꾸미기 시험판에 저장을 연결한다. 실제 박물관 관람씬과 개인 Archive는 교체하지 않는다. 검증 수치와 현재 통합 여부는 `docs/handoffs/DECOR-07.json`이 정본이다.

## 사용자 조작

- 배치·이동·회전·색상·보관은 편집 초안에만 반영된다.
- **적용 / Ctrl+S**는 배치를 검증하고 저장한 뒤 시험 공간 둘러보기로 전환한다. 진행 중인 프리뷰는 먼저 놓거나 취소해야 한다.
- **다시 꾸미기**로 마지막 적용 상태에서 새 편집을 시작한다.
- **전체 취소**는 변경이 있으면 확인창을 띄운다. 계속 편집은 초안을 유지하고, 변경 버리기는 마지막 적용 상태를 복원한다. 저장 파일을 쓰지 않는다.
- 창 종료 후 재실행하면 마지막 적용 상태를 읽는다. 적용하지 않은 초안은 복원하지 않는다.
- 다른 창이 같은 시험 저장을 편집 중이면 읽기 전용으로 연다. 먼저 연 창을 닫은 뒤 재실행하면 편집할 수 있다.

기본 저장은 `Application.persistentDataPath/DecorPrototype-v1/<worldId>/world.json`이다. 별도 시험판의 제품 식별자를 사용한다. 자동 검사는 매번 `logs/decor-ui-날짜/store`에 격리되며 사용자 시험 저장이나 개인 소장품을 읽지 않는다.

## 저장과 화면의 경계

`Storage/DecorPrototypePersistence.cs`는 Unity 독립 조정기다. geometry·world ID·revision을 확인하고 비활성 화면을 준비한 뒤 기존 WorldStore.Commit을 호출한다. 저장된 파일을 다시 읽어 확인된 revision을 화면에 활성화한다. 원본 DTO·명령·파일 포맷을 확장하지 않는다.

`DecorPanel.PrepareWorld`는 별도 비활성 아이템 루트에 부모와 소품을 준비한다. Commit 성공 후 기존 루트를 교체하고 저장된 스냅샷으로 편집기를 초기화한다. 준비 또는 저장 실패 시 임시 루트를 해제하고 기존 초안을 유지한다.

저장 후 활성화에 실패하면 **저장됐지만 화면에 반영하지 못함**을 표시하고 기존 공간을 숨겨 오래된 화면의 편집을 차단한다. **저장된 배치 다시 불러오기**는 디스크 내용을 다시 준비·활성화하며 추가 Commit을 하지 않는다. 손상되거나 다른 버전의 저장은 초기 fixture로 자동 덮어쓰지 않는다.

`UI/DecorPrototypeSession.cs`는 편집/둘러보기/확인창/재로딩을 연결한다. 검색 입력과 확인창에서는 편집 키를 차단한다. Ctrl+S는 카메라 이동 S와 충돌하지 않게 별도 키 조합으로 처리한다. `DecorRestartProbe`와 실패 주입은 명시적 자동 검사에서만 사용한다.

## 재현 및 검토

```powershell
./tools/test-decor-prototype.ps1
node tools/run-ci.mjs
./tools/run-decor-prototype.ps1 -Task Build
./tools/run-decor-prototype.ps1 -Task Verify
./tools/run-decor-prototype.ps1 -Task Launch
```

순수 C# 검사는 검증/준비/저장/활성화 순서와 원본 보존을 확인한다. 실제 Player 검사는 합성 Input System 장치로 UI를 조작하고 실제 디스크 저장 실패 및 활성화 실패 안내를 검사한다. 별도 Player 두 번 실행으로 동시 열기 읽기 전용 안내, 작성자 종료 후 잠금 해제, 정확한 저장 내용 복원을 확인한다. 자동 검사는 사람의 실제 마우스 체감 검토를 대신하지 않는다.

사용자 검토는 전시대와 꽃병을 함께 이동·회전하고 색상을 바꾼 뒤 적용→종료→재실행하는 순서로 시작한다. 이어 다시 꾸미기에서 변경 후 전체 취소, 프리뷰 Esc 취소, 보관 후 같은 개체 재설치를 확인한다. 속도·선택감·버튼 위치는 설정 조정 후보이며 저장 의미·부모 관계·명령 수량 문제는 계약 수정 후보로 기록한다.
