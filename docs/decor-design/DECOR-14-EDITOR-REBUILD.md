# DECOR-14 · 꾸미기 편집기 재구축 1단계

2026-10-18 사용자 승인: 기존 PC 시험판의 화면·입력에 VR 분기를 계속 추가하는 방식에서, 공통 세션을 중심으로 새 PC/VR 뷰를 작성하는 방식으로 변경한다. 기존01~04 코어와06 DecorInteraction,07의 Unity 독립 저장 조정기를 재사용한다. 기존 시험판은 비교 기준으로 보존한다.

## 이번 구현

`apps/quest-viewer/Assets/Museum/Runtime/Decor/Input/`에 다음 구성 요소를 새로 작성했다.

| 파일 | 책임 |
|---|---|
| DecorEditIntent.cs | 장치 독립 입력 봉투·월드 레이·질의 인터페이스 |
| DecorInputCoordinator.cs | 한 활성 소스·단조 증가 순서·입력 세대·프리뷰 포인터 소유권·해제 대기 |
| DecorWorldPointer.cs | 첫 가시 충돌물·거리 제한·바닥/상판 좌표 변환·스냅 |
| DecorEditorSession.cs | 초안·선택·Undo/Redo·작성자 수명·적용/폐기/복구의 단일 소유자 |
| DecorEditorPresenter.cs | PC/VR 뷰에 제공하는 상태와 버튼 활성 조건 |

모드 전환과 일시 중단은 프리뷰만 취소한다. 편집 세션, 선택, Undo/Redo, 디스크 작성자 잠금은 유지한다. 새 입력 세대로 이전 큐를 거절하며 모든 조작을 놓았다는 어댑터 관측 후 입력을 다시 허용한다. 두 VR 손은 동일 소스 순서 번호를 공유한다.

프리뷰 후보 token은 회전/스냅 변경 시 무효화한다. 확정 시 레이를 다시 질의하며 가림/추적/후보 위치가 달라지면 확정하지 않는다. 월드 물체와 UI 중재를 담당하는 어댑터는 UI가 소비한 사건을 다시 월드로 전달하지 않는다. UI 버튼 자체의 의도는 소비된 월드 사건과 별개로 전달한다.

새 표시와 연결할 때 `DecorEditorSession`을 UI GameObject에 소유시키지 않는다. 작업공간 시작 시 한 번 생성하고 작업공간 종료 때만 Dispose한다. 뷰는 상태를 읽고 Submit을 호출하며 생성/파괴에 파일 열기·닫기·Reset·Reload를 수행하지 않는다. InputCoordinator 상태 변경은 세션 내부에서만 가능하다.

## 실제 구현과 남은 어댑터 구분

공통 C# 구현은 Unity·키보드·컨트롤러 API를 참조하지 않는다. `IDecorRaycastScene`의 실제 Physics 질의, 화면 좌표 변환, XR 포즈, UI 소비 판정은 후속 어댑터의 책임이다. 공통 질의가 원거리/벽/가구 가림을 거절하는 자동 검증은 구현했지만 실제 Unity 콜라이더·레이어 구성이 맞다는 검증은 아직 아니다.

`ReleaseControls`는 어댑터가 모든 관련 버튼/스틱이 중립임을 확인했을 때만 보내는 관측 사건이다. 소스별 sequence는 모드 전환에도 계속 증가하며 양손이 각각 별도 카운터를 만들지 않는다. Suspend는 HMD 추적 상실/포커스 상실/앱 pause에 연결하고, Resume 후 새 세대와 해제 대기를 적용한다. 저장 중 재진입/모드 전환을 거절한다.

## 저장 코어 의존성
