# VR Museum · Hybrid Asset / Archive 방향 (2026-10-16)

상태: **설계 방향 확정, 기능 구현 미착수**. 대화에서 정한 장기 운영 방향을 실제 작업용 문서로 정리한다. 이 문서는 기존 `PROJECT_STATUS.md`, `TASKS.md`, 아키텍처 검토 문서 및 현행 코드의 상태를 대체하지 않는다.

## 목적
개인/가족 소장품과 이야기를 수십 년간 보관하여 현재 Quest 3뿐 아니라 미래 VR 기기, PCVR, VRChat 같은 플랫폼에서 계속 활용한다. 특정 Viewer, Unity Scene, VRChat World, 기기 내 앱 데이터는 원본이 아니다.

## 확정한 방향
1. **Museum Archive가 Source of Truth**: 원본 사진/MASTER, 이야기/메타데이터, 별도로 생성되는 PC/MOBILE 등 프로파일을 관리한다. Artifact ID·스키마 버전·환경 독립적인 상대 경로를 유지한다.
2. **하이브리드 지향**: 로컬에 이미 존재하는 전시 콘텐츠는 네트워크 없이 관람 가능하게 설계한다. 네트워크 연결 시 미래의 공급자로부터 필요한 자료만 갱신할 수 있도록 확장 지점을 둔다. 전체 Archive를 기기에 상주시킬 필요는 없다.
3. **DataSource 경계**: 현재 로컬 파일 로딩을 보존하고 나중에 `HttpMuseumDataSource` 같은 공급자를 별도로 추가할 수 있도록 Viewer와 저장 위치를 분리한다. 현재 코드가 이 경계를 완전히 구현했다고 간주하지 않는다.
4. **생명주기 분리**: (a) 보존 원본, (b) 재생성 가능한 PC/MOBILE 배포 파생본, (c) 다운로드한 디스크 캐시, (d) 룸 실행 중 메모리 로드 상태를 구분한다. 캐시 삭제가 Archive 삭제로 이어지면 안 된다.
5. **룸 단위 성능**: 필요한 전시품만 메모리에 올리고 룸 이탈 시 자원을 해제한다. 현행 PC 전시실 로딩 구현은 유지하되, 기기별 성능과 실기기 검증은 별도 과제다.
6. **VRChat 별도 Export**: 허가된 공개 소장품만 VRChat Unity 프로젝트로 선택·변환·빌드한다. 개인 Viewer의 임의 GLB 다운로드와 동일한 런타임을 가정하지 않는다.
7. **보존 및 복원**: Archive는 Unity/서버 없이도 검사·복원 가능한 구조를 지향하고, 원본 손실 방지·해시·백업 절차를 후속 설계한다.

## 지금 하지 않는 일
- 별도의 원격 에셋 서버, DB, NAS, 클라우드/CDN을 **이번 결정만을 이유로 새로 도입하지 않는다**.
- 현재 존재하는 **로컬 Node 관리자용 서버**까지 없앤다는 뜻은 아니다. '추가 원격 에셋 전달 서버 불필요'와 '관리자 백엔드 없음'을 혼동하지 않는다.
- 캐시 용량/제거 정책, 원격 인증, 저장소 제품, Addressables/GLB 전달 포맷은 지금 확정하지 않는다.
- 기존 데이터/프로파일을 자동 마이그레이션하거나 Quest 실기기 완료라고 표시하지 않는다.
