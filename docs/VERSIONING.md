# 박물관 기준 버전과 타이쿤 실험 버전

2026-10-15에 관람 전용 박물관을 기준 버전으로 보존하고, 관람객·운영 기능 개발을 분리했습니다.

## 사용할 폴더

| 구분 | 위치 | 용도 |
|---|---|---|
| 기존 박물관 | `C:\Dev\vr-museum` | 현재 관람 앱·관리페이지, 기존 바로가기 유지 |
| 타이쿤 실험 | `C:\Dev\vr-museum-tycoon` | 관람객·반응·운영 기능 개발 |
| 기준 실행본 백업 | `C:\Dev\vr-museum-snapshots\museum-baseline-20261015` | Windows 실행본과 전시 자료의 복사본 |

## 복원 지점

- Git 태그: `museum-baseline-20261015`
- 기준 브랜치: `codex/museum-baseline`
- 실험 브랜치: `codex/museum-tycoon`
- 기준 소스: 당시 관리페이지, Unity 프로젝트 설정·소스, 도구, 문서, 전시 자료를 저장했습니다.
- Unity 임시파일·Library·로그·빌드 결과는 Git에 넣지 않습니다. 모델·이미지는 Git LFS로 저장합니다.
- 기존 실행파일은 별도 복사하고 파일별 SHA-256으로 확인합니다. 백업의 `snapshot.json`에는 기준 커밋과 확인 결과가 기록됩니다.

두 개발 폴더는 Git 이력을 공유하지만 실제 작업파일과 전시 자료는 각각 따로 있습니다. 실험 버전에서 기존 버전의 전시 자료 경로를 참조하지 않도록 합니다. 실험 기능 빌드도 실험 폴더의 Builds에 생성합니다. 기존 관리 서버 4177을 유지하고, 실험 관리 서버를 추가할 때는 다른 포트를 사용합니다.

## 마음에 들지 않으면

실험 앱을 종료하고 기존 **VR 박물관 (PC 관람)** 또는 **VR 박물관 (Quest Link)** 바로가기를 실행하시면 됩니다. 기존 박물관을 계속 사용할 수 있으므로 파일을 삭제하거나 과거 버전으로 강제 되돌릴 필요가 없습니다.

기준 실행본을 직접 확인하려면 백업 폴더의 `Builds\Windows\VRMuseum.exe`를 사용합니다. 백업 전시 자료까지 정확히 재현하려면 `tools\open-baseline.ps1`로 실행합니다. 이 도구는 관리 서버를 시작하지 않습니다.

현재 브랜치 이름만 바꿔서는 실행파일이 바뀌지 않습니다. 코드 복원은 태그를 기준으로 새 작업 폴더를 만들고 다시 빌드하는 방식으로 진행합니다. 사용자 편집 자료를 덮어쓰는 복원은 별도로 범위를 확인합니다.

## 이후 개발 순서

1. 실험 브랜치에서 관람객 입장 → 전시품으로 이동 → 구경 → 짧은 생각 표시 → 퇴장 구현.
2. 배치 변경에 따른 이동 경로, 관람객 인원 조절, 사용자와의 거리 확인.
3. 관람객 취향·만족도와 인기 전시품 연결.
4. 입장 수입·전시실 확장 등 운영 요소 추가.

관람객 기능은 이 분기 시점에 아직 구현하지 않았습니다. 기준 버전의 VR 기능은 PC 모의검사 완료 상태이며, 실제 Quest 검사는 별도 체크리스트에 따라 나중에 진행합니다.
