# HTML 전시품 관리 화면

## 실행

개발 루트의 Open-Curator.cmd를 더블클릭한다. 로컬 저장 서버가 시작되고 기본 브라우저가 열린다.

최신 타이쿤 관리 주소: http://127.0.0.1:4181 (기존 버전 보관용은4177). 바탕화면 **VR 박물관 관리** 제어창에서 서버 켜기·끄기와 관리페이지 열기를 사용할 수 있습니다.

PowerShell에서는 tools/start-admin.ps1을 실행한다. -NoBrowser는 서버만 시작한다. 같은 주소의 동일 저장소 서버가 실행 중이면 재사용한다. HTML 파일을 직접 더블클릭하는 대신 위 실행 도구를 사용해야 저장할 수 있다.

## 등록

1. '샘플로 시작'에서 항아리/책/고리를 선택하거나 '내 GLB 파일'에서 모델을 선택한다.
2. 이름(최대80자), 이야기(최대400자), 크기(0.01~10)를 입력한다.
3. '전시품 등록'을 누른다. 관리 ID는 자동 생성되며 고급 설정에서 직접 정할 수도 있다.
4. 오른쪽 목록에 추가됐는지 확인한다.
5. Unity 관람 앱을 닫았다 다시 열면 전시된다.

샘플 등록은 모델을 복사한다. 기존 샘플은 변경하지 않는다. GLB는 텍스처/버퍼가 자체 포함된 2.0 형식, 64MiB 이하만 지원한다. 화면에 있는 도형은 목록용 아이콘이며 실제 3D 미리보기는 아니다.

방당 최대30개를 표시한다. 자동 배정 시 첫 여유 방을 채우고 모든 방이 가득 차면 새 방을 만든다. 최대 등록10,000개/방1,000개. 크기 적용 후 가로/깊이95cm, 높이180cm 초과 모델은 Unity에서 오류 대체 표시한다. 관리 화면은 GLB 형식/리소스를 검사하지만 전체 glTF 렌더링이나 최종 크기 적합성을 보증하지 않으므로 관람 앱에서 확인한다.

## 저장 방식

- 로컬 127.0.0.1에만 연결. 외부 업로드·계정·클라우드 없음.
- Node.js 내장 HTTP 및 파일 모듈만 사용. npm 의존성 없음.
- artifacts/{id}/artifact.json과 models/pc.glb를 생성하고 manifest.json에 추가.
- 이미 존재하는 ID/폴더는 거부. 기존 파일 덮어쓰기 없음.
- 모델/JSON 준비 후 폴더를 확정하고 manifest를 마지막에 원자적으로 교체.
- 기존 목록은 museum-archive/.admin-backups/manifest-{uuid}.json에 보존.
- 저장 실패 시 해당 요청의 임시 파일과 새 폴더를 정리. 전원 손실 등으로 남은 미참조 폴더는 자동 삭제하지 않음.
- 도구 실행 중 다른 프로그램에서 manifest를 동시에 편집하지 않는다. 한 관리 서버만 사용한다.
- CSP, 같은 출처/Host 검사, 요청 토큰, 경로/GLB 검사를 적용.

서버 실행 로그는 logs/admin-*.log, 오류 로그는 logs/admin-*-error.log. 현재 런타임은 설치된 Node 또는 사용자 Codex runtime 경로를 사용한다. 독립 배포 시 Node.js 준비가 필요하다.

## 검증

- node tools/test-admin.mjs: 별도 logs fixture에서23개 API 사례. 실제 archive는 변경하지 않음.
- tools/validate-archive.ps1 -ArchivePath <fixture>: 저장 결과 규칙 검사.
- 브라우저에서 샘플 등록 및 실제 파일 선택/등록 확인.
- 동일 Unity 빌드가 등록 모델/메타데이터를 읽는지 별도 archive로 확인.

## 아직 없는 기능

전시품 이름·설명 수정/삭제/방 내 순서 변경, 웹3D 미리보기, 사진/영상, Unity 실행 중 실시간 새로고침은 후속이다.

## 종료

브라우저 탭을 닫아도 로컬 서버는 유지된다. 저장이 끝난 뒤 tools/stop-admin.ps1을 실행하면 이 프로젝트의 관리 서버만 종료한다. 다음에는 Open-Curator.cmd로 다시 연다. PC를 재시작하면 자동 실행되지 않는다.



## 전시실 관리

- 새 전시실 이름을 입력하고 전시실 추가를 누르면 빈 방이 생성된다.
- 전시품 등록 시 배치할 전시실을 선택한다. 기본은 자동 배정이며 꽉 찬 방은 선택 불가.
- 전시실별 보기에서 방별 목록과 남은 자리를 확인한다.
- 각 전시품 아래 배치·수정을 누르고, 도착할 방과 빈 칸을 골라 이동한다.
- 관람 앱을 다시 열고 Page Up/Down 또는 상단 이전·다음으로 방을 이동한다.


## 방별 색상 테마
관리페이지 상단 ‘전시실 색상·테마 조정’을 누르면 ‘방마다 다른 분위기’로 이동한다.
1. 꾸밀 전시실을 선택한다.
2. 기본 박물관/밝은 갤러리/밤의 전시실/따뜻한 서재 중 선택하거나 개별 색을 조정한다.
3. 네 벽·바닥·배경, 전시대, 명판, 방 안내판, 상세창, 조명 등 23개 색을 색상 선택기 또는 #RRGGBB 입력으로 변경할 수 있다.
4. ‘이 방의 테마 저장’을 누른다. 기본색 복원도 저장해야 반영된다.
5. 관람 앱을 종료하고 바탕화면 바로가기로 다시 실행한다. 방을 이동하면 각 방의 저장된 테마가 적용된다.
미리보기는 색 조합 참고용이며 실제 조명과 차이가 있다. 전시품 GLB의 재질 색은 원본을 유지한다. 테마를 저장하지 않은 기존 방은 기본색으로 표시된다.

바탕화면의 **VR 박물관 관리** 바로가기로 제어창을 열고, 서버 켜기 → 관리페이지 열기를 누른다.


## 관리 서버 켜기·끄기 (현재 실행 방식)
바탕화면 **VR 박물관 관리** 또는 Open-Curator.cmd를 열면 제어창이 나온다.
- **서버 켜기**: 서버가 꺼져 있을 때 시작한다.
- **관리페이지 열기**: 서버가 켜져 있을 때 기본 브라우저에서 페이지를 연다.
- **서버 끄기**: 저장 중인 요청이 없을 때 서버를 정상 종료한다. 저장 중이면 잠시 뒤 다시 누른다.
- 제어창이나 브라우저를 닫아도 서버는 유지된다. 종료하려면 서버 끄기를 누른다.
- 서버를 껐다 켠 뒤에는 기존 브라우저를 새로고침하거나 관리페이지 열기를 누른다.
- PC 관람 앱은 관리 서버 없이 사용할 수 있다.
이 절차는 과거의 ‘바로가기 실행 즉시 서버/브라우저 자동 열기’ 안내를 대체한다.


## 전시실 격자 배치와 전시품 수정
- 관리페이지 상단 **전시품 배치·수정** 또는 전시품 카드의 **배치·수정**을 누른다.
- 방은 6열 × 5행이며, 아래쪽 1행이 입구, 위쪽 5행이 안쪽 벽이다.
- 전시품을 다른 칸으로 끌어 놓는다. 마우스 끌기가 어려우면 전시품 선택 → 위치 바꾸기 → 목적지 칸을 누른다. 이미 전시품이 있는 칸은 서로 교환한다.
- **배치 저장**으로 반영한다. **변경 취소·다시 불러오기**로 되돌릴 수 있다. **입구부터 자동 정돈**은 현재 칸 순서대로 앞쪽부터 채운다.
- 선택한 전시품의 이름·설명·크기를 수정하고 **설명·크기 저장**을 누른다. 배치를 먼저 저장한 뒤 설명을 수정한다.
- 다른 방으로 옮길 때 방과 도착할 빈 칸을 고르고 이동한다.
- **휴지통으로 보내기**는 즉시 전시에서 제외하지만 모델과 설명 파일을 보관한다. 아래 휴지통에서 방과 빈 칸을 골라 복원한다. 마지막 전시품까지 휴지통으로 보내도 빈 방을 관람할 수 있다.
- 저장 후 **PC 관람 앱을 종료했다가 다시 실행**해야 적용된다. 모든 방의 크기는 일정하며 빈 칸은 남는다.
- 다른 화면에서 먼저 저장한 변경이 있으면 덮어쓰기를 막는다. 변경 취소·다시 불러오기를 누른 뒤 다시 작업한다.

## 등록 전 3D 미리보기 (2026-10-15)
새 전시품 추가에서 샘플 또는 내 GLB 파일을 선택하면 자동 표시한다. 드래그로 회전, 휠로 확대·축소, 시점 초기화로 복구한다. 등록 전 파일은 브라우저에서 읽으며 등록 버튼을 눌러야 저장한다.
가로·깊이·높이, 파일 용량, 대략적인 삼각형 수를 표시한다. 전시대 크기 범위(95×95×180cm)를 켜거나 끌 수 있고, 권장 크기 적용은 배율 입력을 변경한다. 미리보기 실패/진행 중/치수 초과는 등록 전에 안내한다. 기존 전시품 카드의 3D 보기는 저장된 배율을 적용하며 원본은 변경하지 않는다.
등록 제한과 지원 형식에는 GLB 2.0, 64MB, 배율0.01~10, 이름80자/설명400자, 방30개/전체10,000개 전시품/1,000개방, PC디스크 공간 안내를 표시한다. 휴지통과 백업도 디스크를 사용한다.
현재 미리보기는 Draco/Meshopt/KTX2 압축 모델 미지원. 일반 GLB로 내보내야 한다. 애니메이션은 정지 상태만 표시하며, 실제 관람 앱과 조명·재질·바운드 계산이 다를 수 있다. 대형 모델 성능은 별도 확인한다.
three.js 0.180.0을 로컬에 포함하여 CDN 없이 동작한다. 출처·MIT 라이선스·체크섬은 apps/curator-admin/vendor에 보관한다.

## 관람객 관리·저장 (ADMIN-005 / 2026-10-15)

바탕화면 **VR 박물관 관리** → 서버 켜기 → 관리페이지 → **관람객 관리**. 최신4181과 PC 관람은 같은 실험 자료를 사용하며, 기존 버전 관리4177은 별도입니다. 인원·속도·외형별 설정은 저장 후 약1초 자동 반영되고 다음 실행에도 유지됩니다. [자세한 사용법·저장 및 확장 규칙](VISITOR-ADMIN.md).


## 전시품 감상 반응
최신 반응 기능 빌드에서는 [감상 반응 관리](REACTIONS.md)를 사용한다. 전시품 설명에서 오프라인 후보 생성 → 근거 확인/문구 수정 → 승인/거절 → 저장. 설명 변경 시 이전 반응은 검토 필요 상태가 된다.
