# 관리 화면 사용과 유지보수 · ADMIN-006

## 사용 순서

1. 홈에서 전시품·전시실 수를 확인하거나 왼쪽 메뉴를 선택한다.
2. 전시품 메뉴에서 목록·새 전시품 추가·감상 대사를 선택한다. 목록의 배치·수정은 해당 전시실 배치 탭으로 이동한다. 3D 보기는 추가 화면의 기존 미리보기를 사용한다.
3. 전시실 메뉴 상단에서 방을 고른 뒤 전시품 배치·관람 동선·색상·테마 중 하나를 선택한다. 세 작업은 같은 방을 공유한다.
4. 배치는 기존 이동·교환·자동 정돈·설명/크기 수정·방 이동·휴지통/복원을 사용한다. 관람 동선은 벽의 문 위치·통행 금지·전시품/방 순서를 설정한다. 색상은 프리셋과 미리보기를 먼저 보고 세부 색상 조정을 펼친다.
5. 새 방은 전시실 상단의 새 전시실 만들기를 펼쳐 추가한다. 저장하지 않은 전시실 작업이 있으면 먼저 저장/취소한다.
6. 저장 후 관람 앱을 다시 실행한다. 메뉴 이동은 입력을 유지하지만 새로고침은 입력을 유지하지 않으므로 먼저 저장한다.

## 편집 상태 보호

미저장 배치·설명·동선·테마 또는 저장 중인 작업이 있으면 방과 전시실 작업 탭 변경을 막고 안내한다. 홈/전시품/관람객 메뉴를 다녀와도 기존 편집 DOM과 입력은 유지한다. 저장 실패 시 수정 내용을 유지하며, 성공하거나 취소하면 전환을 다시 허용한다. 탭은 방향키와 Home/End로도 선택한다. 기존 layout-heading/theme-heading/reactions-heading 등 링크는 해당 새 화면으로 연결된다.

## 구현 경계와 인계

admin-workspace.js가 화면/탭/공유 방/편집 상태를 조정한다. layout-editor.js, navigation-editor.js, theme-editor.js는 state/select 어댑터와 room-editor-state 알림을 제공하고 기존 저장 API를 계속 사용한다. 화면 전환마다 편집기를 다시 만들지 않는다. app.js의 갱신은 기존 편집기를 동기화한 뒤 workspace.sync를 호출한다. 새 화면 모듈은 server.mjs의 허용 정적 자산 목록에 포함한다.

API 계약·Archive 형식·Unity 기능은 바꾸지 않았다. 기존 방 선택 요소는 어댑터 호환을 위해 DOM에 유지하되 숨기고 상단 공유 선택을 노출한다. 후속 에이전트는 중복 방 선택 UI나 편집 DOM 재생성을 추가하지 말고 이 경계를 유지한다.
