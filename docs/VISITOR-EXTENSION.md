# 관람객 외형 추가·교체 구조

2026-10-15 · 타이쿤 실험 브랜치 전용

## 구조

관람객의 **행동**과 **외형**을 분리했습니다. 현재 Quaternius가 등록되어 있지만 공통 행동 코드는 특정 제작자·모델·뼈 이름·애니메이션 상태 이름을 참조하지 않습니다.

```text
MuseumVisitors  방별 생성·인원·정리
 └─ MuseumGuest  입장 → 이동 → 관람 → 퇴장
     ├─ VisitorPaths  실제 전시대 콜라이더와 사람 위치를 피하는 경로
     └─ VisitorVisual  외형 프로필의 프리팹·리그·클립으로 표시

VisitorCatalog
 ├─ VisitorAppearance A → 프리팹 A + 자체 Idle/Walk
 ├─ VisitorAppearance B → 프리팹 B + 자체 Idle/Walk
 └─ 나중에 추가할 프로필 …
```

실제 등록 자산은 `apps/quest-viewer/Assets/Museum/Resources/VisitorCatalog.asset`입니다. 처음 등록된 외형 프로필은 `Assets/Museum/Visitors/Casual2.asset`입니다.

## 프로필에 기록할 내용

| 항목 | 의미 |
|---|---|
| id / displayName | 중복되지 않는 식별자 / 표시 이름 |
| prefab | 렌더러와 **Animator 1개**를 가진 캐릭터 프리팹 |
| idle / walk | 그 리그에서 동작하는 대기 / 걷기 클립 |
| height | 표시할 키(m), 현재 기본 1.75 |
| forwardYaw | 모델의 정면 방향 보정(도) |
| walkSpeed | 공간 이동 속도(m/s), 현재 기본 0.9 |
| animationSpeed | 동작 재생 속도, 발걸음과 이동 속도를 맞출 때 조절 |
| available / weight | 사용 여부 / 무작위 선택 상대 비중 |
| creator / sourceUrl / license | 제작자·공식 출처·이용조건 |

유효하지 않은 항목, 중복 ID, 비활성 항목, 가중치 0은 선택 목록에서 제외합니다. 유효한 외형이 하나도 없으면 새 관람객을 생성하지 않습니다. 새 캐릭터가 기존 캐릭터와 같은 리그일 필요는 없으며, **자기 리그에 맞는 클립**을 사용하면 됩니다. 자동으로 서로 다른 뼈 구조를 변환해 준다는 의미는 아닙니다.

## 나중에 에셋을 추가하는 순서

1. 공식 출처에서 파일과 이용조건을 확인하고 원문·해시·출처를 보관합니다. 새 에셋의 조건을 Quaternius 또는 다른 기존 팩에서 추정하지 않습니다.
2. 실험 Unity 프로젝트로 import합니다. Generic 또는 Humanoid 중 해당 에셋에 맞는 리그를 사용하고 실제 Walk / Idle 재생을 먼저 확인합니다.
3. 프리팹을 만듭니다. 하나의 Animator가 시각 모델을 제어하도록 구성하고, 관람객 이동용 콜라이더·별도 움직임 스크립트는 붙이지 않습니다. 원본 에셋에 행동 스크립트가 있으면 관람객용 프리팹에서 제거/비활성화합니다.
4. Unity의 **Assets → Create → Museum → Visitors → Appearance**로 프로필을 만들고 위 필드를 입력합니다.
5. `VisitorCatalog.asset`의 appearances 목록에 프로필을 추가합니다. 사용 비중과 활성 여부를 조절합니다.
6. 먼저 새 외형만 켜고 1명으로 확인합니다. 크기·정면 방향·표면/텍스처·실제 뼈 변형·발걸음·원점 이동·키를 확인합니다.
7. 기존 외형과 섞어서 0~6명·반복 생성/퇴장·방 전환을 검사하고 실험 빌드를 만듭니다. MD와 출처/라이선스를 갱신하고 해당 브랜치에 함께 올립니다.

**일반적인 외형 추가에는 MuseumGuest/VisitorPaths 수정이 필요 없습니다.** 별도 얼굴 시스템이나 여러 Animator 같은 특수 구조가 있는 캐릭터는 추가 어댑터가 필요할 수 있습니다. 현재 구조는 단일 Animator를 가진 캐릭터를 대상으로 합니다.

프로필은 Unity 빌드에 포함되는 자산입니다. 관리페이지에서 전시품 GLB를 올리는 절차가 자동으로 관람객 캐릭터를 등록하는 기능은 아닙니다. 추가 외형을 사용하려면 실험 앱을 다시 빌드합니다.

## 초기 에셋 설정 도구

`Museum/Visitors/Prepare initial appearance`는 확보한 Quaternius 일반 FBX에서 첫 프리팹·프로필·카탈로그를 만듭니다. 최초 카탈로그가 이미 있으면 항목 추가·삭제·활성/가중치·키 등 사용자 설정을 덮어쓰지 않습니다. 다른 외형으로 바꾼 뒤 첫 팩을 제거해도 기존 카탈로그를 사용할 수 있습니다.

`MuseumSetup.BuildDesktop`은 이 초기 준비 단계를 호출합니다. 원본 FBX는 `Assets/Museum/Visitors/Source/`에 있으며 동봉 License.txt도 함께 보관합니다. 다운로드 원본은 `third_party/visitors/quaternius-modular-men/`에 있습니다.

## 현재 관람객 동작

- 실행 시 목표 인원 기본 1명. PC 관람 창 오른쪽 **관람객 · 타이쿤 실험**에서 0~6명과 켜기/끄기를 조절합니다. 이 설정은 현재 실행 중에만 유지됩니다.
- 입장 후 최대3개 정상 전시품을 찾아 이동·관람하고 퇴장합니다. 빈 방이나 실패한 모델만 있는 방은 전시품 관람을 생략하고 퇴장합니다.
- 방 바닥과 실제 전시대 콜라이더에서 0.4m 경로 격자를 만들고, 정적 장애물을 피합니다. 경로의 불필요한 꺾임은 장애물 없는 구간에서 줄입니다.
- 다른 손님과 사용자 위치를 경로 계획에서 피하고, 이동 직전에도 약0.65m 거리 기준으로 접근을 제한합니다. 막히면 다른 전시품으로 넘어가거나 퇴장 경로를 다시 찾고, 전체 체류 제한으로 영구 정체를 방지합니다.
- 방 전환·인원0명에서는 임시 캐릭터와 PlayableGraph를 정리합니다. 캐릭터의 물리 콜라이더는 비활성화하여 기존 전시품 선택과 플레이어 이동을 막지 않습니다.
- 짧은 관람 문구는 관람 상태 표시용입니다. 취향·만족도에 따른 생각 시스템은 아직 없습니다.
- 관람객 설정의 관리페이지 저장·자동 반영은 구현했습니다. 위에서 보는 운영 화면과 수입은 후속입니다. Quest 거리감·진동·프레임 성능은 실기기 검증 전입니다.

## 검증 방법

`tools/test-visitors.ps1`는 별도 시험자료를 만들어 일반·빈 방·30개 밀집 배치·모델 없음의4사례를 실행합니다. 카탈로그 확장/중복/비활성/불완전 제외, 실제 스킨 변형과 크기, 1명 입장·관람·퇴장, 전시대 회피·사용자 거리 판정, 인원 조절/정리, 방 전환 정리를 확인합니다. 새 에셋을 등록할 때는 해당 에셋의 실제 재생·변형·재질 화면도 별도로 확인해야 합니다.

![PC 관람객 구현 확인 화면](assets/visitor-in-gallery.png)

위 화면은 별도 시험실의 캡처 전용 관람객 배치이며, 실제 Quest 화면은 아닙니다. 생산 실행에서는 관람객이 입구에서 생성되어 이동합니다.

## 관람객 관리·저장 (ADMIN-005 / 2026-10-15)

바탕화면 **VR 박물관 관리** → 서버 켜기 → 관리페이지 → **관람객 관리**. 최신4181과 PC 관람은 같은 실험 자료를 사용하며, 기존 버전 관리4177은 별도입니다. 인원·속도·외형별 설정은 저장 후 약1초 자동 반영되고 다음 실행에도 유지됩니다. [자세한 사용법·저장 및 확장 규칙](VISITOR-ADMIN.md).
