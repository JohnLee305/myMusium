# 0003: 여러 전시품과 고정 전시실 수용량

날짜: 2026-09-28

## 결정

Archive 1.0 필드는 유지하고 manifest 배열은 1~128개의 중복 없는 경로로 확장한다. 현재 10m 전시실은 최대6개(3열×2행)만 표시하며 나머지는 화면과 로그에 개수를 안내한다. 순서대로 채우고 실패 항목의 위치는 대체 표시로 보존한다. 추가 방과 페이지 이동은 후속 작업이다.

GalleryDisplay는 목록과 배치·집계를 맡고 ArtifactDisplay는 한 전시품의 로드·표시·정리를 맡는다. 원래 씬의 받침대, 충돌체, 라벨을 복제하므로 데이터 추가에 씬 편집이 필요하지 않다. 첫 슬롯은 기존 씬 참조를 재사용한다. GLB는 순차 로딩해 동시에 여러 파일을 읽는 부하를 피한다.

크기 적용 후 가로/깊이0.95m, 높이1.8m를 넘는 모델은 오류로 표시한다. 임의 축소 대신 데이터의 scale을 수정하도록 문서화한다. 이는 통로와 벽 침범을 방지하기 위한 현재 전시대의 제한이다.

## 오류 경계

- manifest 오류/중복/잘못된 목록 경로: 목록 전체 거부, 오류 대체 표시.
- 개별 JSON/모델 누락·손상·과대 크기: 해당 슬롯만 실패하고 다음 슬롯 로딩 계속.
- 7번째 이후: 로딩 생략, skipped 집계. 검증 CLI는 전체 항목을 검사한다.
- 실행 중 데이터 자동 갱신 없음. 수정 후 재실행.

## 검증 방법

기존 CLI 검사를 12개로 확장. 실제 플레이어는 정상3개/단일/JSON변경/모델누락/JSON손상/과대모델/6개/10개초과/중복/manifest손상 10개 사례를 동일 exe로 검증한다. 정상 및 부분 실패·초과 화면을 직접 확인한다. 결과와 로그 경로는 STATUS/WORKLOG를 따른다. Quest 실기기는 별도 미검증이다.
